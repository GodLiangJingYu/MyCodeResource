# 编译原理实验报告

- 实验题目：Clang 静态检测项开发与自动测试（MISRA C:2012）
- 开发环境：Windows + CLion + MSYS2（UCRT64）
- LLVM/Clang 版本：llvmorg-17.0.5
- 规则组：MISRA C:2012 Rule 7.1 / 8.11 / 15.4

本实验分为三个阶段：

- 阶段一：基于 LLVM/Clang Static Analyzer 开发 3 条 MISRA 规则的检测项，并完成注册与编译。
- 阶段二：安装并配置 nanobot，为后续自动化流程提供大模型能力。
- 阶段三：通过自动化脚本生成测试用例、执行静态检测、并在工作副本中完成缺陷修复。

- `实验报告/阶段一产物/源文件/MISRAC_15_4_Checker.cpp`

#### R_7_1（Octal constants shall not be used）

- 检测目标：识别形如 `010`、`077` 的整数字面量（以 `0` 开头且不属于 `0x/0X/0b/0B`），报告 `MISRA.R_7_1` 缺陷。
- 关键实现：在 AST 遍历中访问 `IntegerLiteral`，使用 `Lexer::getSourceText(...)` 提取源码 Token 文本并判断前缀；为避免宏展开引入复杂定位，本实现跳过宏内字面量（`Loc.isMacroID()`）。

#### R_8_11（外部链接数组声明必须显式指定大小）

- 检测目标：当变量具有外部链接（ExternalLinkage）且类型为不完整数组（IncompleteArrayType）时，报告 `MISRA.R_8_11` 缺陷。
- 关键实现：基于 `check::ASTDecl<VarDecl>` 检查 `VarDecl`，结合 `VD->getFormalLinkage()` 与 `QualType::isIncompleteArrayType()` 判定。

#### R_15_4（循环内用于终止迭代的 break/goto 不超过 1 个）

- 检测目标：对 `for/while/do-while` 的循环体统计 `break/goto` 数量，若超过 1 个则报告 `MISRA.R_15_4` 缺陷。
- 关键实现：对每个循环节点提取 body 并递归遍历统计 `BreakStmt` 与 `GotoStmt`；为避免将嵌套循环/嵌套 `switch` 的 break/goto 计入外层循环，本实现对嵌套结构截断遍历。

## 遇到的问题与解决

### 1) 自动生成用例需要兼容 C++ 解析

自动化工具生成的用例文件扩展名为 `.cpp`，默认按 C++ 语言规则解析，因此生成代码时必须避免会直接导致编译失败的写法（例如不完整数组定义 `static int a[];`）。解决方式是在生成提示中明确约束：

- 必须生成可通过 `clang --analyze` 的代码（无 error）
- 若省略数组大小，必须提供初始化器（如 `static int a[] = {0};`）或使用 `extern` 声明

### 2) 提示词模板与花括号转义

自动化脚本的提示词模板使用字符串格式化机制；当提示词中需要出现字面量花括号（例如展示 C/C++ 初始化器 `{0}`），需要写为 `{{0}}` 才能避免格式化时报错。
