## 阶段二：安装 nanobot

### 1. 创建并使用虚拟环境（推荐）

为了避免依赖冲突，强烈建议使用虚拟环境安装 nanobot：

#### 1.1 创建虚拟环境
打开命令提示符（cmd）或 PowerShell，进入 nanobot-main 目录：

```bash
cd d:\MyCodeResource\bianyiyuanli\exec\exec1\nanobot-main
```

创建虚拟环境：

```bash
python -m venv venv
```

#### 1.2 激活虚拟环境

**Windows PowerShell:**
```bash
.\venv\Scripts\Activate.ps1
```

**Windows CMD:**
```bash
venv\Scripts\activate.bat
```

激活成功后，命令行前面会显示 `(venv)` 标志。

#### 1.3 在虚拟环境中安装 nanobot

```bash
pip install -e .
```

安装完成后若无报错，继续下一步。

**重要提示：以后每次使用 nanobot 时，都需要先激活虚拟环境！**

## 阶段三：自动化检测与缺陷修复

### 1. 准备工作

#### 1.1 确认 clang.exe 路径
确保你已经完成了阶段一的编译，记录下 clang.exe 的绝对路径。

- 如果使用 Visual Studio 2022 编译：路径通常在 `build\Release\bin\clang.exe`
- 如果使用 CLion + MSYS2 编译：路径通常在 `cmake-build-release\bin\clang.exe`

#### 1.2 确认规则信息
- 规则集名称：例如 `MISRA`
- 规则 ID：例如 `R_7_1`、`R_8_11`、`R_15_4`

---

### 2. 使用自动化工具

#### 2.1 进入自动化工具目录

```bash
cd d:\MyCodeResource\bianyiyuanli\exec\exec1\自动化工具
```

#### 2.2 运行自动化检测脚本

使用以下命令格式运行脚本：

```bash

```

**示例：**
```bash
python nanobot_auto_checker.py --clang-path "D:\MyCodeResource\bianyiyuanli\exec\exec1\llvm-project-llvmorg-17.0.5\llvm\cmake-build-release\bin\clang.exe" --rule-set MISRA --rule-id R_7_1
```

---

### 3. 自动化工具工作流程

脚本会自动执行以下步骤：

#### 阶段 A：初始检测
1. **用例解析**：
   - 查找关联关系文件 `关联关系.txt`
   - 定位用例源码文件
   - 如果用例不存在，自动生成四类测试用例

2. **自动生成测试用例**（如果用例不存在）：
   - 读取 `规则集/MISRA规则集.md` 获取规则描述
   - 通过 nanobot 生成四类 C 代码文件：
     - `{rule_id}_violate.cpp` - 违规用例（预期报出缺陷）
     - `{rule_id}_comply.cpp` - 合规用例（预期不应报出）
     - `{rule_id}_fn.cpp` - 漏报边界用例（预期报出缺陷）
     - `{rule_id}_fp.cpp` - 误报边界用例（预期不应报出）
   - 保存到 `用例库/MISRA/` 目录
   - 在 `关联关系.txt` 中自动追加四条对应记录

3. **执行 clang 静态分析**：
   - 运行 clang 静态检测命令
   - nanobot 语义对比输出与预期结果

#### 阶段 B：缺陷修复
- 如果输出符合预期，nanobot 自动修复源码缺陷直至告警消除
- 修复后的文件保存在 `用例库副本/` 目录

#### 阶段 C：用户干预
- 如果输出不符合预期，提示用户修复检测代码后重新检测

---

### 4. 四类测试用例说明

| 类型 | 文件名后缀 | 预期结果 | 说明 |
|------|-----------|----------|------|
| 违规用例 | `_violate.cpp` | 报出缺陷 | 代码包含明显触发目标规则的缺陷，静态分析应检出告警 |
| 合规用例 | `_comply.cpp` | 不应报出 | 代码遵守目标规则，静态分析不应产生告警 |
| 漏报边界 | `_fn.cpp` | 报出缺陷 | 代码实际违反规则但写法隐蔽（宏展开、条件编译、间接引用等），容易导致检查器漏报 |
| 误报边界 | `_fp.cpp` | 不应报出 | 代码看似违反规则但语义安全（条件互斥、作用域隔离等），容易导致检查器误报 |

### 6. 关联关系文件格式

关联关系文件 `关联关系.txt` 为纯文本格式，每行一条记录，字段间以 `——` 分隔：

格式：`规则及名称——规则id——用例源码文件名——用例预期结果`

示例：
```
MISRA——R_7_1——R_7_1_violate.cpp——报出MISRA.R_7_1缺陷
MISRA——R_7_1——R_7_1_comply.cpp——不应报出
MISRA——R_7_1——R_7_1_fn.cpp——报出MISRA.R_7_1缺陷
MISRA——R_7_1——R_7_1_fp.cpp——不应报出
```

---

### 7. 对每条规则重复执行

对于你开发的每条规则（例如 R_7_1、R_8_11、R_15_4），都需要分别运行自动化检测脚本：

```bash
# 检测第一条规则
python nanobot_auto_checker.py --clang-path "<clang路径>" --rule-set MISRA --rule-id R_7_1

# 检测第二条规则
python nanobot_auto_checker.py --clang-path "<clang路径>" --rule-set MISRA --rule-id R_8_11

# 检测第三条规则
python nanobot_auto_checker.py --clang-path "<clang路径>" --rule-set MISRA --rule-id R_15_4
```

## 常见问题

### Q1: 提示找不到 nanobot 命令？
**A:** 
1. 确保已激活虚拟环境（命令行前有 `(venv)` 标志）
2. 如果未激活，先运行：
   ```bash
   cd d:\MyCodeResource\bianyiyuanli\exec\exec1\nanobot-main
   .\venv\Scripts\Activate.ps1
   ```

### Q2: 如何获取 clang 的原始缺陷输出？
**A:** 使用以下命令：
```bash
clang.exe路径 --analyze -Xanalyzer -analyzer-checker=规则集.规则id -o NUL 测试用例文件
```

### Q3: 检测结果中出现误报或漏报怎么办？
**A:** 出现少量误报与漏报是正常现象。在实验报告中说明，并注明出现误报漏报的原因即可。

### Q4: 每次都要激活虚拟环境吗？
**A:** 是的，每次新打开命令行窗口都需要先激活虚拟环境：
```bash
cd d:\MyCodeResource\bianyiyuanli\exec\exec1\nanobot-main
.\venv\Scripts\Activate.ps1
```

### Q5: 如何退出虚拟环境？
**A:** 在命令行输入：
```bash
deactivate
```
