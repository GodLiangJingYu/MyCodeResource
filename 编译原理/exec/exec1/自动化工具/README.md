# Nanobot 自动化检测脚本

基于 nanobot AI 智能体的 Clang 静态分析自动化检测与修复工具。

## 使用方式

```bash
python nanobot_auto_checker.py --clang-path "<clang.exe 绝对路径>" --rule-set <规则集名称> --rule-id <规则 ID>
```

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `--clang-path` | clang.exe 的绝对路径 | `D:\Development\Projects\Work\assistance2026\staticAnalyzer\bin\clang.exe` |
| `--rule-set` | 规则集名称 | `MISRA` |
| `--rule-id` | 规则 ID | `R_1_1` |

### 关联关系文件

关联关系文件固定在脚本同级目录 `关联关系.txt`，无需通过命令行参数指定。

纯文本，每行一条记录，字段间以 `——` 分隔：

格式：`规则及名称——规则id——用例源码文件名——用例预期结果`

示例：
```
GJB8114——R_1_1_5——R_1_1_5_violate.cpp——报出GJB8114.R_1_1_5缺陷
GJB8114——R_1_1_6——R_1_1_6_violate.cpp——报出GJB8114.R_1_1_6缺陷
MISRA——R_1_1——R_1_1_violate.cpp——报出MISRA.R_1_1缺陷
```

### 目录结构

```
自动化工具/
├── nanobot_auto_checker.py    # 主脚本
├── 关联关系.txt                # 关联关系文件（固定路径）
├── 用例库/                    # 测试用例库（按规则集划分子目录）
│   ├── GJB8114/
│   │   ├── R_1_1_5_violate.cpp   # 违规用例
│   │   ├── R_1_1_5_comply.cpp    # 合规用例
│   │   ├── R_1_1_5_fn.cpp        # 漏报边界用例
│   │   └── R_1_1_5_fp.cpp        # 误报边界用例
│   └── MISRA/
│       └── ...
├── 用例库副本/                 # 工作副本（运行时生成，结构与用例库一致）
└── 规则集/                    # 规则集描述文件（用于自动生成）
    ├── GJB8114规则集.md
    └── MISRA规则集.md
```

### 自动生成测试用例

如果 `用例库/{rule_set}/` 中不存在当前 rule_id 对应的测试用例文件，脚本会自动：

1. 读取 `规则集/{rule_set}规则集.md` 获取规则描述
2. 通过 nanobot 一次性生成违规、合规、漏报边界、误报边界四类 C 代码文件
3. 保存到 `用例库/{rule_set}/`，文件名分别为 `{rule_id}_violate.cpp`、`{rule_id}_comply.cpp`、`{rule_id}_fn.cpp`、`{rule_id}_fp.cpp`
4. 在 `关联关系.txt` 中自动追加四条对应记录
5. 使用违规用例继续执行后续检测流程

如果测试用例已存在，则跳过生成直接使用。

#### 四类测试用例

每次自动生成会产出四类用例，覆盖不同测试场景：

| 类型 | 文件名后缀 | 预期结果 | 说明 |
|------|-----------|----------|------|
| 违规用例 | `_violate.cpp` | 报出缺陷 | 代码包含明显触发目标规则的缺陷，静态分析应检出告警 |
| 合规用例 | `_comply.cpp` | 不应报出 | 代码遵守目标规则，静态分析不应产生告警 |
| 漏报边界 | `_fn.cpp` | 报出缺陷 | 代码实际违反规则但写法隐蔽（宏展开、条件编译、间接引用等），容易导致检查器漏报 |
| 误报边界 | `_fp.cpp` | 不应报出 | 代码看似违反规则但语义安全（条件互斥、作用域隔离等），容易导致检查器误报 |

关联关系文件中会同步写入四条对应记录。

### 工作流程

1. **用例解析**：查找关联关系 → 定位用例源码 → 不存在则自动生成
2. **阶段 A — 初始检测**：执行 clang 静态分析命令，nanobot 语义对比输出与预期结果
3. **阶段 B — 缺陷修复**：输出符合预期时，nanobot 自动修复源码缺陷直至告警消除
4. **阶段 C — 用户干预**：输出不符合预期时，提示用户修复检测代码后重新检测

### 前置条件

- Python 3.9+
- nanobot CLI 已安装并在 PATH 中
