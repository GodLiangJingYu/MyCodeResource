# 编译原理实验 - 阶段一：CLion + MSYS2 构建与开发手册

本手册专为你定制，旨在脱离 Visual Studio 2022，在 Windows 环境下使用现代跨平台 C/C++ IDE **CLion** 配合 **MSYS2 (MinGW64/UCRT64)** 完成 LLVM/Clang 的构建与静态检测项开发。

## 1. 基础环境准备 (MSYS2 + CLion)

1. **安装 MSYS2**:
   - 前往 MSYS2 官网下载安装包并安装。
   - 打开 MSYS2 UCRT64 或 MinGW64 终端，安装编译所需工具链：
     ```bash
     pacman -Syu
     pacman -S mingw-w64-x86_64-toolchain mingw-w64-x86_64-cmake mingw-w64-x86_64-ninja
     ```
2. **配置 CLion Toolchains**:
   
   - 打开 CLion -> `Settings` -> `Build, Execution, Deployment` -> `Toolchains`。
   - 新建一个 MinGW 环境，将路径指向你的 MSYS2 安装目录下的 `mingw64` 或 `ucrt64` 文件夹。
   - CLion 会自动检测到 C/C++ 编译器以及 CMake、Ninja。

---

## 2. 克隆 LLVM 源码

打开 MSYS2 终端（或系统的 Git Bash），在全英文路径下执行：
```bash
git clone --branch llvmorg-17.0.5 --depth 1 https://github.com/llvm/llvm-project.git
```

---

## 3. 在 CLion 中导入和配置项目

由于 LLVM 整体项目庞大，我们需要专门构建 Clang 模块：

1. **打开项目**: 在 CLion 中点击 `Open`，选择 `llvm-project/llvm` 目录（**注意是 llvm 子目录，而不是根目录**）中的 `CMakeLists.txt`。
2. **配置 CMake Profile**:
   - 自动弹出 CMake 配置窗口，或者前往 `Settings` -> `Build, Execution, Deployment` -> `CMake`。
   - `Build type` 必须选择 **Release**（Debug 模式编译极慢且占用几百G硬盘空间）。
   - 在 `CMake options` 中添加以下核心参数：
     ```text
     -DLLVM_ENABLE_PROJECTS="clang"
     ```
   - 确认使用的 Toolchain 为刚才配置的 MSYS2 MinGW。
   - 点击 `OK`，等待 CLion 在底部的 CMake 窗口加载完毕项目结构。

---

## 4. 编译 Clang

在 CLion 右上角的运行/编译目标（Run Configurations）下拉列表中：
1. 搜索并选择编译目标为 **`clang`**（一个可执行文件的图标）。
2. 点击绿色的锤子图标 (Build) 开始编译。
   *由于 Clang 代码量巨大，初次编译根据 CPU 性能可能需要 30 分钟到数小时不等，建议保持电源接通且关闭不必要的后台应用。*

编译完成后，`clang.exe` 会生成在 CLion 的 `cmake-build-release/bin` 目录下。

---

## 5. 检测项开发流程 (MISRA C:2012 Rule 7.1, 8.11, 15.4)

你认领的检测项需要在 `clang/lib/StaticAnalyzer/Checkers` 中进行开发。

### 第一步：创建检测项代码

在 CLion 的 Project 视图中，展开 `clang/lib/StaticAnalyzer/Checkers`，右键新建 C++ 文件：
- `MISRAC_7_1_Checker.cpp` (八进制禁止使用)
- `MISRAC_8_11_Checker.cpp` (具有外部链接的数组声明必须指定大小)
- `MISRAC_15_4_Checker.cpp` (循环内的 break/goto 不能超过一个)

### 第二步：将文件加入 CMake 构建树

打开 `clang/lib/StaticAnalyzer/Checkers/CMakeLists.txt`，找到 `add_clang_library(clangStaticAnalyzerCheckers ...)` 这一行，在源文件列表中加入你刚刚创建的文件名：
```cmake
MISRAC_7_1_Checker.cpp
MISRAC_8_11_Checker.cpp
MISRAC_15_4_Checker.cpp
```
*保存后，CLion 通常会自动 Reload CMake 项目。*

### 第三步：在 Checkers.td 中注册规则
打开 `clang/include/clang/StaticAnalyzer/Checkers/Checkers.td`。
查找 `MISRA` 相关的 Package（如果没有则在文件合适位置新建），并注册你的检测项：

```td
// 如果不存在 MISRA 规则包，则添加
def MISRARules : Package<"MISRA">;

let ParentPackage = MISRARules in {
  def MISRAC_7_1 : Checker<"R_7_1">, Documentation<NotDocumented>;
  def MISRAC_8_11 : Checker<"R_8_11">, Documentation<NotDocumented>;
  def MISRAC_15_4 : Checker<"R_15_4">, Documentation<NotDocumented>;
}
```

### 第四步：在 C++ 代码中双向绑定

在每个新建的 `.cpp` 文件的末尾，必须包含注册函数，以 `MISRAC_7_1_Checker` 为例：
```cpp
void ento::registerMISRAC_7_1(CheckerManager &mgr) {
    mgr.registerChecker<MISRAC_7_1_Checker>();
}
bool ento::shouldRegisterMISRAC_7_1(const CheckerManager &mgr) {
    return true;
}
```

---

## 6. 重新编译与测试

由于你修改了源码和配置文件，在 CLion 中只需再次选中 `clang` 目标并点击绿色的 `Build` 锤子图标。
由于这是增量编译，CLion 配合 Ninja 只需要几十秒就能将你的 Checker 编译进新的 `clang.exe`。

### 测试自定义 Checker
编译成功后，打开 CLion 底部的 Terminal，切换到 `cmake-build-release` 目录，准备一个包含违规代码的 `test.c`：
```bash
./bin/clang.exe --analyze -Xanalyzer -analyzer-checker=MISRA.R_7_1 -o NUL test.c
./bin/clang.exe --analyze -Xanalyzer -analyzer-checker=MISRA.R_8_11 -o NUL test.c
./bin/clang.exe --analyze -Xanalyzer -analyzer-checker=MISRA.R_15_4 -o NUL test.c
```
如果检测到了你设定的 `warning` 或 `error`，就证明开发成功！
