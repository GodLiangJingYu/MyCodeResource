# 编译原理作业1：熟悉Clang编译器

本作业旨在熟悉Clang编译器的安装、运行和调试，并通过一个包含多种特性的C程序，观察和分析Clang编译器在各个逻辑阶段（预处理、词法分析、语法分析、中间代码生成、汇编代码生成、目标文件生成、链接执行）的输出结果。

## 1. 实验环境与安装
- **操作系统**: Windows
- **环境配置**: MSYS2 (MinGW-w64 x86_64)
- **编译器**: Clang 21.1.5 (`x86_64-w64-windows-gnu`)
- **安装命令**: `pacman -S mingw-w64-clang-x86_64-clang`

## 2. 实验用的C程序

编写了一个包含宏定义、全局变量、函数声明与调用、条件语句和循环语句的C程序 `example.c`：

```c
#include <stdio.h>

// 宏定义 - 预处理阶段会展开
#define MAX_SIZE 100
#define SQUARE(x) ((x) * (x))

// 全局变量
int globalVar = 42;

// 函数声明
int add(int a, int b);
void printMessage(const char* msg);

// 主函数
int main() {
    int x = 10;
    int y = 20;
    int result;
    
    // 使用宏
    int arr[MAX_SIZE];
    int squared = SQUARE(5);
    
    // 函数调用
    result = add(x, y);
    
    // 条件语句
    if (result > 25) {
        printMessage("Result is greater than 25");
    } else {
        printMessage("Result is 25 or less");
    }
    
    // 循环语句
    for (int i = 0; i < 5; i++) {
        arr[i] = i * 2;
    }
    
    printf("x = %d, y = %d, result = %d\n", x, y, result);
    printf("squared = %d, globalVar = %d\n", squared, globalVar);
    
    return 0;
}

// 函数定义
int add(int a, int b) {
    return a + b;
}

void printMessage(const char* msg) {
    printf("%s\n", msg);
}
```

## 3. 编译器的各个逻辑阶段及其输出结果

Clang作为一个基于LLVM的前端，其编译过程主要分为前端（词法、语法分析）、中端（IR优化）、后端（代码生成）。下面展示了各阶段的命令和输出分析。

### 3.1 预处理阶段 (Preprocessing)

**命令**: `clang -E example.c`

**过程理解**: 处理所有的预处理指令，如`#include`导入头文件内容，`#define`展开宏替换。在这个阶段，`SQUARE(5)`会被替换为`((5) * (5))`，`MAX_SIZE`会被替换为`100`。还会去除注释。

**输出特征**: 输出了展开后的巨长代码（超过26000行），主要包含了stdio.h等标准库的内容，然后在文件的最末尾才出现我们自己的被展开的C代码。

### 3.2 词法分析阶段 (Lexical Analysis)

**命令**: `clang -Xclang -dump-tokens example.c`

**过程理解**: 将字符流分解成有意义的词法单元（Token），如关键字（keyword）、标识符（identifier）、常量（constant）、运算符（operator）等。

**部分输出结果**:
```text
void 'void'	 [StartOfLine]	Loc=<D:/msys64/clang64/include/_mingw.h:604:1>
__attribute '__attribute__'	 [LeadingSpace]	Loc=<D:/msys64/clang64/include/_mingw.h:604:6>
l_paren '('		Loc=<D:/msys64/clang64/include/_mingw.h:604:6>

...
```

可以看到，代码被切分成了像`int`, `identifier`, `l_paren` (左括号) 这样的基本单元，并记录了它们在源代码中的位置(Loc)。

### 3.3 语法分析阶段 (Syntax Analysis)

**命令**: `clang -Xclang -ast-dump example.c`

**过程理解**: 将词法分析生成的Token流转换为抽象语法树（AST）。这个阶段会检查语法是否正确，并体现程序的层次结构。

**部分输出结果**:

抽象语法树中包含了如`FunctionDecl`（函数声明）、`ParmVarDecl`（参数变量声明）、`CompoundStmt`（复合语句）等节点，展示了代码的作用域和控制流。

### 3.4 中间代码生成阶段 (IR Generation)

**命令**: `clang -S -emit-llvm example.c -o example.ll`

**过程理解**: 将AST转换为LLVM的中间表示（IR）。LLVM IR是一种平台无关的、强类型的类似汇编的语言。

**部分输出结果**:
```llvm
@globalVar = dso_local global i32 42, align 4
@.str = private unnamed_addr constant [26 x i8] c"Result is greater than 25\00", align 1
@.str.1 = private unnamed_addr constant [21 x i8] c"Result is 25 or less\00", align 1

; Function Attrs: noinline nounwind optnone uwtable
define dso_local i32 @main() #0 {
  %1 = alloca i32, align 4
  %2 = alloca i32, align 4
  %3 = alloca i32, align 4
  store i32 10, ptr %2, align 4
  store i32 20, ptr %3, align 4
  %8 = load i32, ptr %2, align 4
  %9 = load i32, ptr %3, align 4
  %10 = call i32 @add(i32 noundef %8, i32 noundef %9)
  store i32 %10, ptr %4, align 4
  %11 = load i32, ptr %4, align 4
  %12 = icmp sgt i32 %11, 25
  br i1 %12, label %13, label %14
  ...
}
```
可以看到，局部变量通过`alloca`指令在栈上分配内存（以`%`开头的寄存器），然后使用`load`和`store`进行读写，函数通过`call`调用，条件分支通过`icmp`和`br`实现。

### 3.5 汇编代码生成阶段 (Assembly Generation)

**命令**: `clang -S example.c -o example.s`

**过程理解**: LLVM后端将优化后的IR代码转换为特定目标机器（这里是x86_64）的汇编代码。

**部分输出结果**:
```assembly
main:                                   # @main
.seh_proc main
# %bb.0:
	pushq	%rbp
	subq	$464, %rsp                      # imm = 0x1D0
	leaq	128(%rsp), %rbp
	callq	__main
	movl	$10, 328(%rbp)
	movl	$20, 324(%rbp)
	movl	$25, -84(%rbp)
	movl	328(%rbp), %ecx
	movl	324(%rbp), %edx
	callq	add
	movl	%eax, 320(%rbp)
	cmpl	$25, 320(%rbp)
	jle	.LBB0_2
```
这是标准的x86_64汇编语言，利用了具体的寄存器如`%rbp`、`%rsp`、`%ecx`、`%edx`等，以及指令如`pushq`、`movl`、`callq`等。

### 3.6 汇编器和链接器阶段

- **目标文件生成 (Assembler)**: `clang -c example.c -o example.o`
  将汇编代码转换为机器可以直接执行的二进制指令（对象文件）。生成的`example.o`是`x86-64 COFF object file`格式。
  
- **链接与执行 (Linker)**: `clang example.c -o example.exe`
  将各个目标文件及所需的标准库文件链接在一起，生成最终的可执行文件。
  

运行生成的 `./example.exe` 输出：
```text
Result is greater than 25
x = 10, y = 20, result = 30
squared = 25, globalVar = 42
```

## 4. 总结与体会

通过以上各个阶段的操作，可以清晰地观察到一段C代码是如何被编译器逐步降解的：
1. **预处理**扩展代码，解决宏和库引入。
2. **词法与语法分析**（Clang前端）验证代码合法性，建立树状逻辑结构（AST）。
3. **IR生成**将其标准化为一种通用的中间表示（LLVM IR）。这一步是LLVM架构设计的精髓，使得前端与后端解耦。
4. **后端与链接**则将通用表示转化为针对特定硬件的机器码并组装成可执行文件。
