## 第一章 编译器技术发展和工作原理

### 1.1 编译器的定义
- **编译器**：把计算机高级语言（源语言）编写的程序（源程序）翻译成该计算机的汇编语言或机器语言（目标语言）书写的目标程序的计算机程序
- 常见编译器：GCC（GNU Compiler Collection，支持9种语言，850万行+）、Clang、JavaC等

### 1.2 编译器逻辑阶段划分
编译器由以下6个逻辑阶段组成：

源代码 -> 词法分析 -> 语法分析 -> 语义分析 -> 中间代码生成 -> 代码优化 -> 目标代码生成 -> 目标代码

各阶段共享的数据结构：
- **常数表**：存储源程序中的常数
- **符号表**：存储标识符的属性信息
- **错误处理器**：处理各阶段检测到的错误

### 1.3 各阶段任务概述

| 阶段 | 主要任务 |
|------|----------|
| 词法分析 | 逐个读入源程序字符，按构词规则切分成单词（token）序列 |
| 语法分析 | 分析单词序列的语法结构，判断是否为合法程序，构造语法树 |
| 语义分析 | 静态语义检查（类型检查、上下文有关问题检查等） |
| 中间代码生成 | 生成复杂性介于源程序和目标程序之间的机内表达形式 |
| 代码优化 | 对中间代码进行优化，提高目标代码执行效率 |
| 目标代码生成 | 将优化后的中间代码翻译为目标机器代码 |

### 1.4 编译器技术发展历史（了解）
- 编译1.0时代（20世纪50年代）：完成程序语言到机器语言的翻译，侧重编译器前端实现
- 编译2.0时代（20世纪60年代）：研究循环优化、指令调度、目标平台优化
- 编译3.0时代（21世纪初）：研究多核处理器的并行优化、LLVM编译器架构、AI编译器等

## 第二章 词法分析

### 2.1 词法分析器的作用
- **任务**：从源代码中读入输入字符，按照构词规则切分成一系列单词（token），提交给语法分析使用
- **输出**：token序列，每个Token包括字符串（词义）和类型（词法）
- **功能**：
  1. 识别出源程序中的单词
  2. 删除无用的空白字符及注释
  3. 检测出错误字符串

### 2.2 正规表达式

#### 2.2.1 基本概念
- **字母表（字符集）**：有限个输入符号的集合
- **符号串**：由字母表中符号组成的有限序列
- **空符号串**：不包含任何符号的符号串，长度为0
- **正规式的作用**：用有限的表达式去解决无限个字符串匹配的问题
- **正规集**：每个正规表达式匹配（或代表）一个字符串的集合

#### 2.2.2 正规表达式的定义
设有字母表为，辅助字母表={ф, ε, |, ., *, ()}：

1. 和ф是上的正规式，所表示的正规集分别为{}和{}
2. 若a，则a是上的正规式，所表示的正规集为{a}
3. **若r和s是上的正规式**，所表示的正规集分别为L(r)和L(s)，则：
   - r|s 是正规式，表示 L(r|s) = L(r) ∪ L(s)
   - rs 是正规式，表示 L(rs) = L(r)L(s)
   - r* 是正规式，表示 (L(r))* 
   - (r) 是正规式，表示 L(r)
4. 有限次使用上述步骤而定义的表达式是上的正规式

**运算符优先级**：先"()"，再"*"，再"."，最后"|"，左结合

#### 2.2.3 正规表达式的扩展
- r+：表示r被重复1次或更多次，r+ = rr*
- .：任意字符（匹配除换行符之外的任意单个字符）
- [a-z]：字符范围表示法
- ?：可选子表达式

#### 2.2.4 单词的正规表达式举例
- letter = [a-zA-Z] | "_"
- digit = [0-9]
- identifier = letter(letter|digit)*
- reserved = else|if|int|return|void|while
- nat = [0-9]+
- signedNat = (+|-)?nat

### 2.3 有穷自动机

#### 2.3.1 确定性有穷自动机（DFA）的定义
DFA是一个五元组：M = (S, Σ, T, s₀, A)
- **Σ**：有限个输入符号组成的字母表
- **S**：有限个状态的集合
- **T**：S×Σ→S，转换函数
- **s₀∈S**：初始状态
- **A⊆S**：接受状态（终止状态）集合

#### 2.3.2 状态转换图
- 圆圈表示状态，箭头指示初始状态，双圆圈表示终止状态
- 若T(s,a)=s'，则从状态s到状态s'画标记为a的矢线

### 2.4 从正规表达式到DFA

#### 2.4.1 从正规表达式到NFA
基本正规式转换为NFA的方法：
1. 对正规式ε：0 ->ε-> 1
2. 对正规式ф：0 -> 1（无转换）
3. 对正规式a：0 ->a-> 1

复合正规式的转换：
- R=r|s：构造并行路径
- R=rs：串联连接
- R=r*：构造循环

#### 2.4.2 从NFA到DFA
**ε-闭包**：从状态s出发经过零个或多个ε-转换能达到的状态的集合

**子集构造算法**：
1. 计算初始状态s₀的ε-闭包，作为DFA的初始状态
2. 对于每个未处理的状态和每个输入符号a，计算转换后的状态及其ε-闭包
3. 重复直到没有新状态产生
4. 包含NFA接受状态的状态为DFA的接受状态

#### 2.4.3 DFA最小化
**DFA最小化算法（3步骤）**：
1. 首先将状态集合S分为两个等价类：接受状态集A及S-A
2. 细分等价类：
   - 若存在输入符号a，s1或s2中的一个无法识别a
   - 若存在输入符号a，s1、s2识别a后到达的状态分别在不同等价类中
   - 则将K细分为两个等价类
3. 递归步骤2，直到所有等价类都不能再细分

### 2.5 用代码实现有穷自动机
实现方法：
1. **直接编码**：用if-else语句直接模拟DFA（适合状态少的情况）
2. **嵌套case测试**：用双层嵌套的switch-case语句
   - 第1层switch测试当前状态
   - 第2层switch测试输入字符
3. **转换表格法**：用二维数组T[state, ch]存储转换函数

## 第三章 上下文无关文法

### 3.1 上下文无关文法的定义
上下文无关文法G是一个四元组：G = (V_T, V_N, P, S)
- **V_T**：终结符集合
- **V_N**：非终结符集合
- **P**：文法产生式A→α的集合，A∈V_N，α∈(V_T∪V_N)*
- **S**：开始符号，S∈V_N

**作用**：帮助构造有效的分析算法来检验一个给定字串是否是由某个上下文无关文法产生的

### 3.2 推导和规约

#### 3.2.1 直接推导
若有v,w满足：v=γαδ, w=γβδ，其中α→β是文法G的产生式，则称v直接推导到w，记作v ⇒ w

#### 3.2.2 推导的定义
- w₀ ⇒+ w_n：表示w₀到w_n经历一步或多步推导
- w₀ ⇒* w_n：表示w₀到w_n零步或多步推导

#### 3.2.3 句型和句子
- **句型**：若S ⇒* α，α∈V*，则称α为文法G的句型
- **句子**：若S ⇒+ α，α∈V_T*，则称α为文法G的句子

#### 3.2.4 最左推导和最右推导
- **最左推导**：任何一步直接推导α ⇒ β，都是用α中的最左非终结符进行推导
- **最右推导（规范推导）**：任何一步直接推导α ⇒ β，都是用α中最右非终结符进行推导

### 3.3 文法定义的语言
文法G[S]定义的语言L(G)为所有句子构成的集合：
L(G) = {x | S ⇒+ x, 其中S为开始符号, x ∈ V_T*}

**等价文法**：如果L(G₁) = L(G₂)，则称G₁和G₂为等价文法

### 3.4 递归产生式和递归文法
- **递归产生式**：若存在产生式A→xAy∈P
- **左递归产生式**：x=ε且y≠ε，A→Ay
- **右递归产生式**：x≠ε且y=ε，A→xA
- **直接递归文法**：文法中至少存在一条递归产生式
- **间接递归文法**：若有A ⇒+ xAy

**重要结论**：一般的文法都是递归的，文法G只有递归定义，L(G)中的句子才是无穷的

### 3.5 分析树
- 每个节点都用终结符、非终结符或ε标出
- 根结点用文法的开始符号S标出
- 每个叶结点都用终结符或ε标出
- 每个非叶结点都用非终结符标出
- 每一步直接推导对应一个子树

### 3.6 二义性文法
对于文法G，若存在某个句子w∈L(G)，w对应多个不同的最左推导（或最右推导），则称该文法为**二义性文法**。

## 第四章 语法分析

### 4.1 自上而下的语法分析

#### 4.1.1 递归下降分析
- **基本思想**：为每个非终结符编写一个递归函数，从文法的开始符号出发，通过递归调用匹配输入串
- **要求**：文法必须是LL(1)文法
- **注意事项**：
  1. 间接递归的文法需要改造
  2. 存在左公共因子时需要提取
  3. 存在左递归时需要消除

#### 4.1.2 EBNF表示法
- **选择**：A → α | β
- **重复**：{ }表示重复0次或多次
- **可选**：[ ]表示可选

#### 4.1.3 消除左递归
**简单直接左递归的消除**：
- 原文法：A → Aα | β
- 消除后：A → βB, B → αB | ε

**多项直接左递归的消除**：
- 原文法：A → Aα1|Aα2|...|Aαn|β1|β2|...|βm
- 消除后：A → β1B|β2B|...|βmB, B → α1B|α2B|...|αnB|ε

#### 4.1.4 提取左因子
- 原文法：U → xy|xw|...|xz
- 提取后：U → xV, V → y|w|...|z

### 4.2 LL(1)分析

#### 4.2.1 First集合的求法
设G = {V_T, V_N, S, P}是上下文无关文法：
1. 若X ∈ V_T，则First(X) = {X}
2. 若X ∈ V_N，且有产生式X → a...，a ∈ V_T，则a ∈ First(X)
3. 若X → ε，则ε ∈ First(X)
4. 若X → Y...，Y ∈ V_N，则(First(Y) - {ε}) ∈ First(X)
   - 若X → Y1Y2...Yn，且对1<=i<=m<n，有ε ∈ First(Yi)，则∪(First(Yi) - {ε}) ∈ First(X)
   - 若X → Y1Y2...Yn，且对1<=i<=n，有ε ∈ First(Yi)，则∪First(Yi) ∈ First(X)

#### 4.2.2 Follow集合的求法
1. 将{#}加入Follow(S)
2. 若X → μAβ，则把First(β) - {ε}加入Follow(A)中
3. 若有β → ε，则把Follow(X)加入Follow(A)中

#### 4.2.3 验证文法是否为LL(1)
定义：G的任意两个具有相同左部的产生式A → α|β满足：
1. 若α, β均不能推导出ε，则First(α) ∩ First(β) = ∅
2. α和β至多有一个能推导出ε
3. 若α → ε，则First(α) ∩ Follow(A) = ∅

**算法步骤**：
1. 消除左递归
2. 计算First集和Follow集
3. 按照定义验证

#### 4.2.4 构造LL(1)预测分析表M
- 表的竖行是文法的非终结符
- 表的横行是文法的终结符和#
- 对于G中的A → α：
  1. 对每个a ∈ First(α)，把A → α加入M[A, a]
  2. 若ε ∈ First(α)，对任何b ∈ Follow(A)，把A → ε加入M[A, b]

#### 4.2.5 LL(1)文法完整分析过程
分析栈、输入、动作（移进/归约/接受/出错）

### 4.3 自下而上的语法分析（LR分析）

#### 4.3.1 LR分析概览
- **L**：自左(Left)向右分析输入单词序列
- **R**：分析过程都是构造最右(Right)推导的逆过程（规范归约）
- **k**：在决定当前分析动作时向右看的单词个数

**特点**：
- 应用面广：能够识别所有采用上下文无关文法描述的程序设计语言的语法结构
- 能有效实现：无回溯的移进-归约方法
- 容易查错：能够及时发现语法错误和准确指出错误位置

#### 4.3.2 LR(0)分析
**LR(0)项目**：对于文法G，其产生式的右部添加一个特殊符号"."就构成LR(0)项目
- 若A → βγ是产生式，则A → β.γ就是LR(0)项目

**项目分类**：
1. **移进项目**：圆点之后为终结符，A → α.aβ
2. **待约项目**：圆点之后为非终结符，A → α.Bβ
3. **归约项目**：圆点在最后，A → α.
4. **接受项目**：S' → S.

**构造识别活前缀的DFA**：
1. 拓广文法G为G'，引进S' → S
2. 定义闭包函数CLOSURE(I)和转移函数GO(I, x)
3. 从CLOSURE({S' → .S})开始构造DFA

**LR(0)分析表构造**：
1. 若GO(i, x)=j，x∈V_N，则Goto[i, x]=j；x∈V_T，则Action[i, x]=Sj
2. 对于终态中的归约项目，对所有输入符号置Action[i, x]=rk
3. 若含项目S' → S.，则Action[i, $]=acc

#### 4.3.3 SLR(1)分析
- SLR(1)文法：存在冲突项目（移入-归约）时，使用Follow集合来解决冲突
- 任何一个LR(0)文法一定是一个SLR(1)文法

#### 4.3.4 LR(1)分析
**LR(1)项目**：在LR(0)项目中放置一个向右搜索符号a，形式为[A → α.β, a]

**LR(1)分析表构造规则**：
1. 对于[A → α.xβ, a] ∈ 状态i，且GO(i, x)=j
   - 若x∈V_T，则Action[i, x]=Sj
   - 若x∈V_N，则Goto[i, x]=j
2. 对于[A → α., a] ∈ 状态i，若A→α是第j个产生式，则Action[i, a]=rj
3. 对于[S → α., $] ∈ 状态i，则Action[i, $]=acc

#### 4.3.5 LALR(1)分析
- **基本思想**：将LR(1)项目集中的同心集合并，压缩为较小的DFA
- **同心集合并**：相同的心(LR(0)项目)不变，合并后项目集的搜索符等于合并前LR(1)项目搜索符的并集
- 任何一个SLR(1)文法一定是一个LALR(1)文法

#### 4.3.6 文法类型关系
LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ LR(1)

## 第五章 语义分析

### 5.1 属性文法

#### 5.1.1 属性文法的定义
属性文法是一个三元组：A = (G, V, F)
- **G**：上下文无关文法
- **V**：属性的有限集合
- **F**：有关属性的语义规则的有限集合

**属性**：与文法符号X关联的属性a记作X.a，例如：
- 变量的数据类型
- 表达式的值
- 存储器中变量的位置
- 程序中间或目标代码片段

#### 5.1.2 合成属性
- **定义**：给定产生式A → X1X2...Xn，满足A.a = f(X1.a1,...,Xn.ak)，则属性a是合成的
- **S-属性文法**：一个属性文法中所有的属性都是合成的
- **计算方法**：通过后序遍历语法树计算

#### 5.1.3 继承属性
- **定义**：语法分析树一个节点的某一属性值是由父结点和/或兄弟结点的属性值来计算的
- **计算方法**：通过前序遍历或前序和中序遍历的组合进行计算

#### 5.1.4 属性计算方法
1. **抽象语法树遍历**：构造语法树后，以某种次序遍历计算所有属性
2. **一遍语法分析**：在语法分析的同时计算属性值

**L-属性文法**：继承属性不依赖于合成属性
**S-属性文法**：通常使用自底向上的分析方法

### 5.2 符号表

#### 5.2.1 符号表的作用
1. 登记编译过程输入和输出信息
2. 在语义分析过程中用于语义检查和中间代码生成
3. 作为目标代码生成阶段地址分配的依据

#### 5.2.2 符号表的数据结构
- **哈希表**：使用哈希函数将键转化为数组索引，处理冲突使用分离链表
- **嵌套作用域处理**：
  - 方案一：符号表插入操作不改写前面的声明，删除操作只需删除最近的一个
  - 方案二：为每个作用域建立一个新的符号表，从内到外链接在一起

### 5.3 数据类型和类型检查

#### 5.3.1 类型检查的任务
- **类型推论**：计算和维护数据类型信息
- **类型检查**：确保程序的每一部分在语言的类型规则作用下有意义
- **静态检查**：在程序执行之前进行正确性检查（如C语言）
- **动态检查**：在目标程序运行时完成检查（如Java、Python）

#### 5.3.2 类型检查的语义规则
1. **类型声明**：声明引起标识符的类型插入符号表
2. **表达式类型检查**：检查操作符作用于相容的操作数
3. **语句类型检查**：检查赋值语句左右两边类型相容

## 第六章 代码生成

### 6.1 中间代码概览
- **中间代码**：复杂性介于源程序和目标程序之间的一种机内表达形式
- **作用**：
  1. 使编译程序的算法清晰，便于分工、修改、维护和移植
  2. 使编译器更容易重定向
  3. 可以在中间代码上进行与机器无关的代码优化

### 6.2 三地址码

#### 6.2.1 三地址码的形式
每条三地址码最多包含一个运算符：
- x = y op z
- x = op y
- x = y
- goto L
- if x goto L
- if_false x goto L

#### 6.2.2 作为合成属性的代码生成
- 将生成的代码看作一个字符串属性
- 用合成属性文法定义代码生成的语义规则
- 在语法分析期间直接生成或通过语法树的后序遍历生成

### 6.3 数据结构引用的代码生成

#### 6.3.1 数组引用
C数组引用a[i]的地址：base_address(a) + i * sizeof(int)

## 第七章 运行时环境

### 7.1 程序执行时的存储器组织

#### 7.1.1 存储区域划分
- **代码区**：存放程序的目标代码
- **静态数据区**：存放全局变量和静态变量
- **栈区**：存放函数的形参、局部变量和局部临时变量
- **堆区**：供用户动态申请存储空间（malloc/free, new/delete）

#### 7.1.2 活动记录
在C语言中，采用以函数为单位的动态存储分配方案：
- 函数被调用时，在栈顶分配活动记录
- 函数返回时，活动记录从栈中释放

**活动记录包含**：
1. 实参信息
2. 返回地址
3. 控制链（指向主调函数活动记录的指针）
4. 临时变量和局部数据

### 7.2 基于栈的运行时环境

#### 7.2.1 关键寄存器
- **sp（栈指针）**：存储栈顶部的地址（x86系统使用sp或esp）
- **fp（帧指针/控制链指针）**：存储当前活动记录的控制链（x86系统使用bp或ebp）

#### 7.2.2 fp指针的作用
1. 通过该指针可以访问主调函数的活动记录，即允许当前被调函数执行完毕时恢复主调函数的活动记录
2. 通过该指针可以访问当前执行函数的实参和局部变量

#### 7.2.3 函数调用过程
**调用时**（在栈顶分配活动记录）：
1. 将实参值压入新活动记录中
2. 将返回地址压入新活动记录中
3. 完成到被调用过程代码的转移
4. 将主调函数ebp作为控制链压入新活动记录中
5. 改变ebp使其指向新活动记录（将esp复制到ebp中）
6. 将局部变量和局部临时变量压入新活动记录中

**返回时**：
1. 将ebp复制到esp中
2. 将主调函数的控制链装载到ebp中
3. 完成到主调函数的转移
4. 改变esp以弹出实参

#### 7.2.4 对名字的访问
- 非局部名字都是全局的，具有固定的静态地址
- 每个实参和局部声明的偏移量可由编译程序计算
- 例如：mOffset=+8, yOffset=-4（相对于ebp）

#### 7.2.5 嵌套声明的处理
按照与临时表达式相类似的办法处理嵌套块声明，在进入块时在栈中分配它们

#### 7.2.6 可变长度参数的处理
C编译程序通过把调用的自变量按相反顺序压入运行时栈来处理

### 7.3 动态存储器

#### 7.3.1 对象类型的运行时表示
- 对象包含字段和方法表指针
- 方法调用翻译为函数调用，传递this指针

#### 7.3.2 继承特性的实现
- 子类扩展父类，增加新的字段和方法
- 方法表包含所有可调用的方法

## 第八章 中间代码优化

### 8.1 基本块的优化

#### 8.1.1 基本块的定义
基本块是一个三地址码序列，控制流从第一条三地址码进入，从最后一条三地址码退出，中间没有停止或分支

#### 8.1.2 基本块的划分
1. 求出各个基本块的入口语句：
   - 程序第一个语句
   - 能由条件转移语句或无条件转移语句转移到的语句
   - 紧跟在条件转移语句后面的语句
2. 对每个入口语句，确定其所属的基本块
3. 未被纳入基本块中的语句可以删除

#### 8.1.3 基本块内的优化
1. **合并已知量**：编译时能计算的表达式直接计算
2. **删除公共子表达式**：相同的表达式只计算一次
3. **削减计算强度**：用较快的运算代替较慢的运算
   - x的平方 变成 x*x
   - 2*x 变成 x+x
   - x/2 变成 x*0.5
4. **删除无用代码**：赋值后未被使用的语句可以删除

#### 8.1.4 DAG图
基本块内部优化实现的主要工具为DAG图，用DAG图表示各个值的计算/依赖关系

**三地址码分类构建DAG**：
- **0型**：A = B（赋值）
- **1型**：A = op B（单目运算）
- **2型**：C = A op B（双目运算）

**由基本块构造DAG算法**：
1. 对于任意三地址码，如果节点B在DAG中无定义，则构造标记为B的叶节点
2. 根据三地址码类型构造相应的DAG节点
3. 合并已知量
4. 删除公共子表达式
5. 删除无用赋值

### 8.2 与循环有关的优化

#### 8.2.1 流图
流图是把控制流信息加到基本块集合所形成的有向图：
- 节点：基本块
- 有向边：控制流
- 首节点：第一个基本块

#### 8.2.2 循环结构的识别

**定义8.1 必经节点**：如果流图中从初始节点出发，每一条到达节点n的路径都必须经过m，则称m是n的必经节点，记为m dom n

**定义8.2 直接必经节点**：从初始节点到达n的所有路径上，节点n的最后一个必经节点

**定义8.3 回边**：假设m dom n，如存在从节点n到m的有向边n→m，则该边称为回边

**定义8.4 自然循环**：回边n→m的自然循环是找出所有不经过m而到达n的所有节点，连同节点m与n，构成以m为首节点的循环

**自然循环的寻找算法**：
输入: 回边{N→M}
输出: 回边对应的自然循环
设置loop={N,M}
push(stack, N)
while non-empty(stack) do
    x = top(stack)
    pop(stack)
    for x的每个前驱节点p
        if p is_not_in loop then
            loop += p
            push(stack, p)

#### 8.2.3 数据流分析

**定义8.5 定值**：使变量x获得值的四元式称为对x的定值

**定义8.6 引用点**：引用某个变量x的四元式的位置

**定义8.7 到达-定值**：假定x有定值点d，如果存在某条路径从d可以到达某点p，称x的定值d到达p

**定义8.8 引用-定值链（ud链）**：设变量x有一个引用点u，变量x的所有能到达u的一切定值称为x在u点处的ud链

**到达-定值数据流方程**：
IN[B] = ∪ OUT[p] where p is in P[B]
OUT[B] = GEN[B] ∪ (IN[B] - KILL[B])

其中：
- **P[B]**：基本块B的所有直接前驱节点集合
- **GEN[B]**：在B内定值并能到达B出口点之后的所有定值点集合
- **KILL[B]**：在B外定值而在B中又重新定值的变量定值点集合

**迭代求解算法**：
对于任意基本块B：
    IN[B] = 空
    OUT[B] = GEN[B]
    change = TRUE
while(change)
    change = FALSE
    for each B do
        IN[B] = ∪ OUT[p] where p is in P[B]
        oldout = OUT[B]
        OUT[B] = GEN[B] ∪ (IN[B] - KILL[B])
        if(OUT[B] != oldout) change = TRUE

#### 8.2.4 循环优化实现

**循环不变表达式优化**：
1. **识别循环不变表达式**：根据ud链，如果四元式运算分量是常数或其所有定值点在循环外部
2. **外提条件**：
   - Q所在基本块节点是循环所有出口节点的必经节点
   - 循环中Q的定值点只有Q这一个

**计算强度削减**：
- 对于数组元素地址计算，当数组元素下标满足：
  1. 数组是常界数组
  2. 下标变量中的下标表达式是循环控制变量的线性表达式
- 则地址的计算使用加法来代替乘法

## 重点公式速记

### 正规表达式运算
- r|s = L(r) ∪ L(s)
- rs = L(r)L(s)
- r* = (L(r))* 

### First集求法
1. First(终结符) = {终结符本身}
2. First(非终结符) = 从该非终结符能推导出的所有首终结符
3. 若能推导出ε，则ε也在First集中

### Follow集求法
1. Follow(开始符号) = {#}
2. 若A → αBβ，则First(β)-{ε} ⊆ Follow(B)
3. 若A → αB或A → αBβ且ε∈First(β)，则Follow(A) ⊆ Follow(B)

### LL(1)分析表构造
- 对A → α：First(α)中每个终结符a，M[A,a] = A→α
- 若ε∈First(α)：Follow(A)中每个终结符b，M[A,b] = A→α

### LR分析表构造
- 移进：Action[i, a] = Sj（当GO(i,a)=j）
- 归约：Action[i, a] = rk（当项目为归约项目）
- 接受：Action[i, $] = acc
- Goto：Goto[i, A] = j（当GO(i,A)=j）

### 数据流方程
- IN[B] = ∪ OUT[p]，p∈P[B]
- OUT[B] = GEN[B] ∪ (IN[B] - KILL[B])
