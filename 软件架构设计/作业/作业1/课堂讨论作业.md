# 课堂讨论作业

## 1 题目：共享自习室预约管理系统

### 1）系统背景

随着高校和城市学习空间需求增加，出现了大量“共享自习室”。用户可以在线预约座位、按时段使用，并通过系统进行管理。本系统用于支持一个共享自习室平台的日常运营。

### 2）系统参与者

系统用户：普通用户（自习者），管理员（自习室运营人员）。

外部系统：是与拟开发的“共享自习室预约管理系统”交互的其他软件系统，包括：

1. 用户账户系统：提供注册、登录、身份验证功能；
2. 支付系统：支持预约费用在线支付；
3. 门禁控制系统（外部硬件系统）：用户到达后扫码或验证进入自习室。

### 3）基本需求

#### 1. 用户预约座位

用户登录系统后，可以浏览不同自习室（位置、价格、开放时间）、查看某自习室某时间段的座位使用情况（空闲/已预约）、选择时间段 + 座位进行预约。

约束：

- 一个时间段内，一个座位只能被一个用户预约；
- 用户可预约多个时间段（可连续或不连续）。

#### 2. 预约确认与支付

用户提交预约后，系统生成预约订单（状态：待支付），用户可在线支付，支付成功后，状态变为：已预约。

若在限定时间内未支付，则预约自动取消。

#### 3. 使用与签到

用户在预约时间段内到达自习室，通过扫码或身份验证进入（调用门禁系统），系统记录签到时间。

规则：

- 未签到可能会被判定为“爽约”；
- 连续爽约可能影响信用（可扩展思考）。

#### 4. 预约管理

用户可以查看自己的预约记录（当前/历史）、在预约开始前取消预约（部分或全部时间段）。

#### 5. 管理员管理

管理员可以管理自习室信息（新增/修改/下架）、查看所有预约订单、标记异常情况（如，未使用、违规占座等）。

## 2 具体要求

请你根据以上原始需求完成以下建模任务：

| 用例名称           | 说明                     |
| ------------------ | ------------------------ |
| 预约座位           | 涉及时间段冲突、库存检查 |
| 支付               | 涉及状态转换、外部系统   |
| 签到入场           | 涉及门禁系统、时间判断   |
| 取消预约           | 涉及退款/状态变化        |
| 自动取消未支付订单 | 涉及系统定时行为         |

### 2）静态建模

绘出软件系统上下文类图，需体现与外部系统交互关系；确定：

- 实体类（持久数据）
- 边界类（与外部交互）
- 控制类（用例驱动核心）
- 应用逻辑类（规则与策略）

要求：

- 给出类的关键属性；
- 明确类之间关系（关联/依赖/聚合等）；
- 体现用例与类的映射关系。

### 3）动态建模

自主选定一个关键用例，绘出其通信图，描述对象之间消息传递，与类图对应；

并给出消息序列文字说明，需包含：

- 主要交互步骤；
- 条件判断；
- 异常路径。

若需要设计状态相关控制类，请给出相关状态图。
