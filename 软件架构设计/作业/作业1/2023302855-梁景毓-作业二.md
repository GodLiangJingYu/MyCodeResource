## 2. 实体类（Entity Classes）

实体类代表持久化数据，是系统的核心业务对象：

```mermaid
classDiagram
    class User {
        -userId: String
        -username: String
        -password: String
        -phone: String
        -creditScore: int
        -role: UserRole
        +getUserId(): String
        +updateCreditScore(delta: int): void
        +isEligible(): boolean
    }

    class StudyRoom {
        -roomId: String
        -name: String
        -location: String
        -pricePerHour: double
        -openTime: String
        -closeTime: String
        -status: RoomStatus
        +isAvailable(timeSlot: TimeSlot): boolean
        +updateInfo(): void
        +deactivate(): void
    }

    class Seat {
        -seatId: String
        -roomId: String
        -seatNumber: String
        -type: SeatType
        -status: SeatStatus
        +isAvailable(slot: TimeSlot): boolean
        +lock(slot: TimeSlot): boolean
        +unlock(slot: TimeSlot): void
    }

    class Reservation {
        -reservationId: String
        -userId: String
        -seatId: String
        -timeSlots: List~TimeSlot~
        -totalAmount: double
        -status: ReservationStatus
        -createTime: DateTime
        -lockExpireTime: DateTime
        +calculateAmount(): double
        +cancel(): boolean
        +isExpired(): boolean
        +confirmPayment(): void
    }

    class TimeSlot {
        -date: String
        -startTime: String
        -endTime: String
        +overlap(other: TimeSlot): boolean
        +duration(): double
        +isAfterNow(): boolean
    }

    class PaymentRecord {
        -paymentId: String
        -reservationId: String
        -amount: double
        -paymentMethod: String
        -status: PaymentStatus
        -payTime: DateTime
        +isSuccess(): boolean
        +markSuccess(): void
        +markFailed(reason: String): void
    }

    class CheckInRecord {
        -checkInId: String
        -reservationId: String
        -userId: String
        -checkInTime: DateTime
        -type: CheckInType
        +isOnTime(): boolean
    }

    class ExceptionRecord {
        -exceptionId: String
        -reservationId: String
        -type: ExceptionType
        -description: String
        -handledBy: String
        -createTime: DateTime
        +resolve(): void
    }

    User "1" --o "*" Reservation : 拥有
    StudyRoom "1" --o "*" Seat : 包含
    Seat "1" --o "*" TimeSlot : 对应
    Reservation "1" --o "*" TimeSlot : 覆盖
    Reservation "1" --o "0..1" PaymentRecord : 关联
    Reservation "1" --o "0..1" CheckInRecord : 关联
    Reservation "1" --o "0..*" ExceptionRecord : 关联
```

### 实体类说明

| 实体类 | 说明 | 关键属性 |
|--------|------|----------|
| User | 系统用户（自习者/管理员） | userId, username, phone, creditScore, role |
| StudyRoom | 自习室信息 | roomId, name, location, pricePerHour, openTime, closeTime, status |
| Seat | 自习室座位 | seatId, roomId, seatNumber, type, status |
| Reservation | 预约订单 | reservationId, userId, seatId, timeSlots, totalAmount, status, createTime |
| TimeSlot | 时间段 | date, startTime, endTime |
| PaymentRecord | 支付记录 | paymentId, reservationId, amount, status, payTime |
| CheckInRecord | 签到记录 | checkInId, reservationId, userId, checkInTime, type |
| ExceptionRecord | 异常记录 | exceptionId, reservationId, type, description, handledBy |

## 5. 应用逻辑类（Application Logic Classes）

应用逻辑类封装可复用的业务规则和策略，与控制类分离，关注"规则"而非"流程编排"：

```mermaid
classDiagram
    class ConflictDetectionLogic {
        <<application logic>>
        +detectConflict(seatId: String, slots: List~TimeSlot~): boolean
        +findAvailableSeats(roomId: String, slot: TimeSlot): List~Seat~
        +validateTimeSlot(slot: TimeSlot): boolean
    }

    class PricingLogic {
        <<application logic>>
        +calculatePrice(seat: Seat, slots: List~TimeSlot~): double
        +applyDiscount(user: User, amount: double): double
        +calculateRefund(reservation: Reservation): double
    }

    class CreditPolicyLogic {
        <<application logic>>
        +evaluateNoShowPenalty(userId: String): int
        +updateCreditScore(userId: String, delta: int): void
        +isUserBanned(userId: String): boolean
    }

    class PaymentTimeoutPolicy {
        <<application logic>>
        +getPaymentDeadline(createTime: DateTime): DateTime
        +isExpired(reservation: Reservation): boolean
    }
```

### 应用逻辑类说明

| 应用逻辑类 | 封装的规则 | 不放在控制类的原因 |
|-----------|-----------|-------------------|
| ConflictDetectionLogic | 时间段冲突检测、座位可用性查询 | 冲突检测是多个用例的公共规则（预约、签到均需检查） |
| PricingLogic | 价格计算、折扣策略、退款金额计算 | 定价策略可能变化，需独立维护；多处使用 |
| CreditPolicyLogic | 爽约判定规则、信用分扣减策略 | 信用策略是业务规则而非流程，可能频繁调整 |
| PaymentTimeoutPolicy | 支付超时判定、时限配置 | 超时策略是规则配置，多处依赖（支付、自动取消） |

## 8. 类关系说明

### 8.1 实体类关系

| 关系类型 | 源类 | 目标类 | 说明 |
|----------|------|--------|------|
| 关联 | User | Reservation | 一个用户拥有多个预约 |
| 组合 | StudyRoom | Seat | 自习室包含多个座位，座位依赖自习室存在 |
| 关联 | Seat | TimeSlot | 一个座位对应多个可用时段 |
| 关联 | Reservation | TimeSlot | 一个预约覆盖多个时段 |
| 关联 | Reservation | PaymentRecord | 一个预约对应一条支付记录 |
| 关联 | Reservation | CheckInRecord | 一个预约对应一条签到记录 |
| 关联 | Reservation | ExceptionRecord | 一个预约可关联多条异常记录 |

### 8.2 边界类与外部系统映射

| 边界类 | 对应外部系统 | 交互方式 |
|--------|--------------|----------|
| AccountSystemInterface | 用户账户系统 | API调用（身份验证） |
| PaymentSystemInterface | 支付系统 | API调用（支付处理） |
| AccessControlInterface | 门禁控制系统 | 硬件接口（门禁验证） |

### 8.3 控制类与应用逻辑类依赖

| 控制类 | 依赖的应用逻辑类 | 使用的规则 |
|--------|------------------|------------|
| ReservationController | ConflictDetectionLogic | 冲突检测 |
| ReservationController | PricingLogic | 价格计算 |
| PaymentController | PaymentTimeoutPolicy | 超时判定 |
| CheckInController | CreditPolicyLogic | 信用策略 |
| AutoCancelController | PaymentTimeoutPolicy | 超时判定 |
