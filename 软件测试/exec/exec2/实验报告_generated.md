## 1. 实验目的

本次实验旨在通过黑盒测试方法，对电子飞镖靶计分系统的核心功能和通信接口进行全面验证。主要目的包括：

- **功能验证**：确保系统能够正确处理飞镖类型和数量的输入，并根据靶区命中信息准确计分。
- **数据驱动测试**：验证系统在接收外部测试数据时，能否依据预设用例执行测试。
- **边界值分析**：测试系统对输入数据边界条件（如最大飞镖数量）的处理能力。
- **接口容错测试**：检验通信协议的稳定性和系统的异常处理能力，确保在接收到格式错误、内容无效的数据包时，系统不会崩溃或产生意外行为。

## 2. 实验环境

- **硬件**：电子飞镖靶模拟系统
- **软件**：ETest 嵌入式测试平台
- **脚本语言**：Lua
- **通信协议**：自定义串行通信协议

## 3. 实验内容与过程

本次测试分为功能测试和接口容错测试两大部分。

### 3.1 功能测试

#### 3.1.1 飞镖信息输入功能测试 (`1shoot.lua`)

**测试描述：**

此脚本用于测试系统对飞镖信息（类型和数量）的接收和处理逻辑。脚本支持两种模式：
1.  **数据驱动模式**：若检测到外部 `data.yml` 文件，则自动读取其中的测试用例进行测试。
2.  **默认场景模式**：若未检测到外部数据，则执行内置的几个核心场景，包括正常输入和边界值输入。

**核心测试场景：**

- **场景1（轻镖）**：输入类型为1（轻镖），数量为10。预期系统倒计时设置为30秒。
- **场景2（重镖）**：输入类型为2（重镖），数量为20。预期系统倒计时设置为90秒。
- **场景3（边界值）**：输入飞镖数量为21（超出最大值20）。预期系统将数量截断为20进行处理（依据需求文档 2.2）。

**关键代码片段：**

```lua
-- 场景3: 数量边界测试 (21枚) -> 预期截断为 20
print(">>> 默认场景3: 边界测试 (21枚) (预期: 截断为20)")
write_msg(channels.shoot, protocols.shoot, {type = 1, number = 21})
etimer.delay(1000)
```

#### 3.1.2 靶区命中信息接收功能测试 (`2target.lua`)

**测试描述：**

此脚本用于验证系统能否正确接收并处理来自不同靶区的命中信号，并进行分数累加。

**核心测试场景：**

- 脚本会依次模拟命中 1 至 5 号靶区。
- **测试覆盖**：1-内牛眼, 2-外牛眼, 3-三倍区, 4-双倍区, 5-单倍区。
- 每个靶区会连续发送 3 次命中信号，用以检验分数的累加功能是否正常。

**关键代码片段：**

```lua
-- 遍历靶区 1 到 5
for zone_id = 1, 5 do
  print(string.format("=== 开始测试靶区: %d ===", zone_id))
  -- 每个靶区连续发送 3 次，观察分数累加
  for i = 1, 3 do
    write_msg(channels.target, protocols.target, {zone = zone_id})
    etimer.delay(500)
  end
  etimer.delay(1000)
end
```

### 3.2 接口容错测试

#### 3.2.1 飞镖信息输入接口容错测试 (`3interface_shoot.lua`)

**测试描述：**

此脚本通过构造异常数据包，测试飞镖信息输入接口的健壮性。测试方法为错误注入，预期系统能识别并丢弃所有异常数据包，而不影响自身稳定运行。

**核心测试场景：**

- **正向测试**：发送完全正确的数据包，验证链路通信正常。
- **包头错误**：发送包头为 `0x5511` 的数据包（正确应为 `0xAA55`）。
- **数据标志错误**：发送数据标志为 `0xAA` 的数据包（正确应为 `0xBB`）。
- **包尾错误**：发送包尾为 `0x5511` 的数据包（正确应为 `0x55AA`）。
- **校验和错误**：发送校验和为 `0` 的数据包。

**关键代码片段：**

```lua
-- Test 1: 包头错误
-- 需求文档: 包头应为 0xAA55
print("测试项1: 发送错误包头 (0x5511)")
write_msg(channels.shoot, protocols.shoot, {header=0x5511})
-- 预期结果：ask弹窗确认是否丢包（未收到信息则为通过）
```

#### 3.2.2 靶区命中信息接口容错测试 (`4interface_target.lua`)

**测试描述：**

与上一节类似，此脚本通过构造异常数据包来测试靶区命中信息接口的健壮性。

**核心测试场景：**

- **正向测试**：发送合法的靶区命中数据（Zone 1）。
- **校验和错误**：发送一个错误校验和的数据包。
- **包头/包尾错误**：发送错误的帧头或帧尾。
- **数据标志错误**：分别发送数据标志1 (`data1`) 和标志2 (`data2`) 错误的数据包。
- **逻辑错误（无效靶区）**：发送靶区编号 `9`（有效范围1-5），测试系统的业务逻辑校验。

**关键代码片段：**

```lua
-- Test 4: 无效靶区号 (逻辑错误)
-- 需求文档: 有效区为 1-5
print("测试项4: 发送无效靶区号 (9)")
write_msg(channels.target, protocols.target, {zone=0x9})
```

## 5. 总结与分析

本次实验综合运用了多种黑盒测试技术，有效地验证了电子飞镖靶系统的功能完整性和稳定性。

1.  通过 **等价类划分** 和 **边界值分析** (`1shoot.lua`)，我们验证了核心业务逻辑在典型和边缘情况下的正确性，特别是对飞镖数量上限的处理符合需求文档 2.2 的规定。
2.  通过 **数据驱动测试** 的设计，展示了测试脚本的高可扩展性，能够灵活应对未来测试数据的变更。
3.  通过 **错误注入/错误猜测** (`3interface_shoot.lua`, `4interface_target.lua`)，系统地测试了通信协议栈的健壮性。实验证明，系统对于不符合协议规范（如错误的头尾、校验和）或业务规范（如无效靶区）的数据包均具备正确的丢包处理机制，未出现误判或系统崩溃现象。
