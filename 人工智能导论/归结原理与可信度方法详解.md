## 谓词公式化为子句集的方法

### 1.1 基本概念

#### 1.1.1 相关定义

**原子（Atom）：**
- 不能再分解的命题
- 是构成谓词公式的基本单位

**文字（Literal）：**
- 原子谓词公式及其否定
- 分为正文字和负文字
- 例如：P(x) 是正文字，¬P(x) 是负文字

**子句（Clause）：**
- 任何文字的析取式
- 是由若干个文字通过析取符号（∨）连接而成的公式
- 例如：P(x) ∨ ¬Q(y) ∨ R(z) 是一个子句

**空子句（NIL）：**
- 不包含任何文字的子句
- 永假，表示矛盾
- 在归结推理中，如果归结出空子句，说明原公式不可满足

**子句集（Clause Set）：**
- 由子句构成的集合
- 通常用大括号表示，例如：{P ∨ ¬Q, ¬P ∨ R, Q ∨ ¬R}

#### 1.1.2 子句集的性质

1. **完备性**：任何谓词公式都可以等价地转化为子句集
2. **无冗余性**：子句集中不包含冗余信息
3. **可判定性**：子句集的不可满足性可以通过归结原理判定

### 1.2 化简子句集的九个步骤

#### 步骤1：消去蕴含和等价符号

**目的：** 将公式中所有的蕴含符号（→）和等价符号（↔）转换为基本的逻辑连接词

**转换规则：**
1. **蕴含转换：**
   ```
   P → Q  等价于  ¬P ∨ Q
   ```

2. **等价转换：**
   ```
   P ↔ Q  等价于  (¬P ∨ Q) ∧ (P ∨ ¬Q)
   ```

**示例：**
```
原公式：(P → Q) ↔ R
转换后：(¬(¬P ∨ Q) ∨ R) ∧ ((¬P ∨ Q) ∨ ¬R)
```

#### 步骤2：减少否定符号¬的辖域

**目的：** 将否定符号的作用范围缩小到只作用于单个原子

**转换规则（德·摩根定律）：**
1. **双重否定：**
   ```
   ¬(¬P)  等价于  P
   ```

2. **否定的析取：**
   ```
   ¬(P ∨ Q)  等价于  ¬P ∧ ¬Q
   ```

3. **否定的合取：**
   ```
   ¬(P ∧ Q)  等价于  ¬P ∨ ¬Q
   ```

4. **量词的否定：**
   ```
   ¬(∀x)P(x)  等价于  (∃x)¬P(x)
   ¬(∃x)P(x)  等价于  (∀x)¬P(x)
   ```

**示例：**
```
原公式：¬(P ∨ (Q ∧ R))
转换后：¬P ∧ (¬Q ∨ ¬R)
```

#### 步骤3：对变量标准化

**目的：** 消除变量名的冲突，使不同量词中的变量具有不同的名称

**规则：**
- 如果在不同量词的辖域内出现了同名变量，则应该对它们进行改名
- 改名后的变量名必须是唯一的，不能与其他变量名冲突

**示例：**
```
原公式：(∀x)P(x) ∧ (∃x)Q(x)
转换后：(∀x)P(x) ∧ (∃y)Q(y)
```

**注意：** 改名时只能改变约束变量的名称，不能改变自由变量

#### 步骤4：消去存在量词（Skolem函数）

**目的：** 将存在量词消去，使公式中只有全称量词

**Skolem化方法：**

**情况1：存在量词不在任何全称量词的辖域内**
- 直接用一个常量（Skolem常量）替换存在量词约束的变量
- 常量名通常以a, b, c等开头

**示例：**
```
原公式：(∃x)P(x)
转换后：P(a)  （a是Skolem常量）
```

**情况2：存在量词在全称量词的辖域内**
- 用一个函数（Skolem函数）替换存在量词约束的变量
- Skolem函数的自变量是所有包含该存在量词的全称量词的变量

**示例：**
```
原公式：(∀x)(∃y)P(x, y)
转换后：(∀x)P(x, f(x))  （f(x)是Skolem函数）
```

**更复杂的示例：**
```
原公式：(∀x)(∀y)(∃z)P(x, y, z)
转换后：(∀x)(∀y)P(x, y, f(x, y))
```

**注意：**
- Skolem函数的名称必须与公式中已有的函数名不同
- Skolem化后的公式与原公式不是等价的，但它们在不可满足性上是等价的

#### 步骤5：化为前束形

**目的：** 将所有量词移到公式的最前面

**前束形（Prenex Normal Form）：**
- 所有量词都在公式的前面
- 量词后面是无量词的公式（称为母式）

**转换规则：**
1. **量词辖域的扩展：**
   ```
   (∀x)P(x) ∧ Q  等价于  (∀x)(P(x) ∧ Q)  （x不在Q中自由出现）
   (∃x)P(x) ∧ Q  等价于  (∃x)(P(x) ∧ Q)  （x不在Q中自由出现）
   ```

2. **量词的交换：**
   ```
   (∀x)(∀y)P(x, y)  等价于  (∀y)(∀x)P(x, y)
   (∃x)(∃y)P(x, y)  等价于  (∃y)(∃x)P(x, y)
   ```

**示例：**
```
原公式：(∀x)P(x) ∧ (∀y)Q(y)
转换后：(∀x)(∀y)(P(x) ∧ Q(y))
```

#### 步骤6：把母式化为合取范式

**目的：** 将无量词的公式转化为合取范式（CNF）

**合取范式（Conjunctive Normal Form）：**
- 若干个析取式的合取
- 即：(子句1) ∧ (子句2) ∧ ... ∧ (子句n)

**转换步骤：**
1. 利用分配律将合取分配到析取中：
   ```
   P ∧ (Q ∨ R)  等价于  (P ∧ Q) ∨ (P ∧ R)
   P ∨ (Q ∧ R)  等价于  (P ∨ Q) ∧ (P ∨ R)
   ```

2. 反复应用分配律，直到公式成为合取范式

**示例：**
```
原母式：P ∨ (Q ∧ R)
转换后：(P ∨ Q) ∧ (P ∨ R)
```

**更复杂的示例：**
```
原母式：(P ∨ Q) ∧ (R ∨ S) ∨ T
转换后：(P ∨ Q ∨ T) ∧ (R ∨ S ∨ T)
```

#### 步骤7：消去全称量词

**目的：** 移除所有全称量词

**规则：**
- 在前束形中，所有量词都在公式前面
- 由于已经消去了存在量词，现在只剩下全称量词
- 可以直接消去所有全称量词，因为所有变量都被隐含地认为是全称量化的

**示例：**
```
原公式：(∀x)(∀y)(P(x) ∨ Q(y))
转换后：P(x) ∨ Q(y)
```

**注意：** 消去全称量词后，公式中的所有变量都被认为是全称量化的

#### 步骤8：消去合取符号∧

**目的：** 将合取范式中的合取符号去掉，得到子句集

**规则：**
- 合取范式是若干个子句的合取
- 消去合取符号后，每个子句成为集合中的一个元素
- 用逗号分隔各个子句

**示例：**
```
原公式：(P ∨ Q) ∧ (¬P ∨ R) ∧ (¬Q ∨ ¬R)
转换后：{P ∨ Q, ¬P ∨ R, ¬Q ∨ ¬R}
```

#### 步骤9：更换变量名称

**目的：** 使不同子句中的变量具有不同的名称

**规则：**
- 对每个子句中的变量进行改名
- 改名时保持子句内部的变量关系不变
- 改名后的变量名必须唯一

**示例：**
```
原子句集：{P(x) ∨ Q(y), ¬P(x) ∨ R(y)}
改名后：{P(x1) ∨ Q(y1), ¬P(x2) ∨ R(y2)}
```

**注意：** 这一步是为了在后续的归结过程中避免变量名冲突

### 1.3 完整示例

**示例1：简单公式的转换**

**原公式：**
```
(∀x)(P(x) → (∃y)Q(x, y))
```

**步骤1：消去蕴含符号**
```
(∀x)(¬P(x) ∨ (∃y)Q(x, y))
```

**步骤2：减少否定符号的辖域**
```
(∀x)(¬P(x) ∨ (∃y)Q(x, y))
（无需修改）
```

**步骤3：对变量标准化**
```
(∀x)(¬P(x) ∨ (∃y)Q(x, y))
（无需修改）
```

**步骤4：消去存在量词**
```
(∀x)(¬P(x) ∨ Q(x, f(x)))
```

**步骤5：化为前束形**
```
(∀x)(¬P(x) ∨ Q(x, f(x)))
（已经是前束形）
```

**步骤6：把母式化为合取范式**
```
(∀x)(¬P(x) ∨ Q(x, f(x)))
（已经是合取范式）
```

**步骤7：消去全称量词**
```
¬P(x) ∨ Q(x, f(x))
```

**步骤8：消去合取符号**
```
{¬P(x) ∨ Q(x, f(x))}
```

**步骤9：更换变量名称**
```
{¬P(x) ∨ Q(x, f(x))}
（只有一个子句，无需改名）
```

**最终子句集：**
```
{¬P(x) ∨ Q(x, f(x))}
```

---

**示例2：复杂公式的转换**

**原公式：**
```
(∀x)((∃y)P(x, y) → (∃z)(Q(x, z) ∧ R(y, z)))
```

**步骤1：消去蕴含符号**
```
(∀x)(¬(∃y)P(x, y) ∨ (∃z)(Q(x, z) ∧ R(y, z)))
```

**步骤2：减少否定符号的辖域**
```
(∀x)((∀y)¬P(x, y) ∨ (∃z)(Q(x, z) ∧ R(y, z)))
```

**步骤3：对变量标准化**
```
(∀x)((∀y)¬P(x, y) ∨ (∃z)(Q(x, z) ∧ R(y, z)))
（变量名已经标准化）
```

**步骤4：消去存在量词**
```
(∀x)((∀y)¬P(x, y) ∨ (Q(x, f(x)) ∧ R(y, f(x))))
```

**步骤5：化为前束形**
```
(∀x)(∀y)(¬P(x, y) ∨ (Q(x, f(x)) ∧ R(y, f(x))))
```

**步骤6：把母式化为合取范式**
```
(∀x)(∀y)((¬P(x, y) ∨ Q(x, f(x))) ∧ (¬P(x, y) ∨ R(y, f(x))))
```

**步骤7：消去全称量词**
```
(¬P(x, y) ∨ Q(x, f(x))) ∧ (¬P(x, y) ∨ R(y, f(x)))
```

**步骤8：消去合取符号**
```
{¬P(x, y) ∨ Q(x, f(x)), ¬P(x, y) ∨ R(y, f(x))}
```

**步骤9：更换变量名称**
```
{¬P(x1, y1) ∨ Q(x1, f(x1)), ¬P(x2, y2) ∨ R(y2, f(x2))}
```

**最终子句集：**
```
{¬P(x1, y1) ∨ Q(x1, f(x1)), ¬P(x2, y2) ∨ R(y2, f(x2))}
```

### 1.4 重要注意事项

1. **Skolem化的非等价性：**
   - Skolem化后的公式与原公式在逻辑上不等价
   - 但它们在不可满足性上是等价的
   - 这对于归结推理已经足够

2. **变量标准化的必要性：**
   - 避免不同量词辖域内的变量名冲突
   - 确保每个变量的作用范围清晰

3. **合取范式的唯一性：**
   - 一个公式可以有多种合取范式形式
   - 但它们在逻辑上是等价的

4. **空子句的意义：**
   - 空子句表示矛盾
   - 如果子句集中包含空子句，则该子句集不可满足

5. **子句集的应用：**
   - 子句集是归结推理的基础
   - 通过对子句集进行归结，可以判定公式的不可满足性

## 鲁宾逊归结原理

### 2.1 归结原理的概述

#### 2.1.1 归结原理的提出

**提出时间：** 1965年
**提出者：** J.A. Robinson（鲁宾逊）
**历史意义：**
- 是自动定理证明的里程碑
- 为机器推理提供了有效的算法
- 成为人工智能领域的重要基础理论

#### 2.1.2 归结原理的基本思想

**核心思想：**
- 检查子句集S中是否包含空子句
- 若包含空子句，则S不可满足
- 若不包含空子句，在S中选择合适的子句进行归结
- 一旦归结出空子句，就说明S是不可满足的

**理论基础：**
- 基于反证法
- 如果假设前提为真而结论为假导致矛盾，则结论必然为真
- 矛盾通过空子句表示

#### 2.1.3 归结原理的优点

1. **完备性：** 如果子句集不可满足，归结原理一定能找到空子句
2. **简单性：** 归结规则简单，易于实现
3. **通用性：** 适用于命题逻辑和谓词逻辑
4. **自动化：** 适合计算机自动推理

### 2.2 命题逻辑中的归结原理

#### 2.2.1 归结的定义

**定义：**
设C1与C2是子句集中的任意两个子句，如果C1中的文字L1与C2中的文字L2互补（即一个是另一个的否定），那么从C1和C2中分别消去L1和L2，并将两个子句中余下的部分析取，构成一个新的子句C12，这个新子句C12称为C1和C2的归结式。

**互补文字：**
- P和¬P是互补文字
- ¬P和P是互补文字

**示例：**
```
C1: P ∨ Q ∨ R
C2: ¬P ∨ S
归结式: Q ∨ R ∨ S
```

#### 2.2.2 归结的推论

**推论1：归结式是亲本子句的逻辑结论**
- 归结式C12是其亲本子句C1与C2的逻辑结论
- 即：C1 ∧ C2 ⇒ C12

**证明：**
```
假设C1 = L1 ∨ C1'，C2 = ¬L1 ∨ C2'
则C1 ∧ C2 = (L1 ∨ C1') ∧ (¬L1 ∨ C2')
          = (L1 ∧ ¬L1) ∨ (L1 ∧ C2') ∨ (C1' ∧ ¬L1) ∨ (C1' ∧ C2')
          = (L1 ∧ C2') ∨ (C1' ∧ ¬L1) ∨ (C1' ∧ C2')
          ⇒ C1' ∨ C2' = C12
```

**推论2：归结保持不可满足性**
- 若用C12替代C1与C2后得到新子句集S1
- 则S1在不可满足的意义上等价于S
- 即：S不可满足当且仅当S1不可满足

**意义：**
- 可以安全地用归结式替代亲本子句
- 不会改变子句集的不可满足性

#### 2.2.3 命题逻辑归结的示例

**示例1：简单归结**

**子句集：**
```
S = {P ∨ Q, ¬P ∨ R, ¬Q ∨ R, ¬R}
```

**归结过程：**
```
步骤1: 从P ∨ Q和¬P ∨ R归结
       归结式: Q ∨ R

步骤2: 从Q ∨ R和¬Q ∨ R归结
       归结式: R

步骤3: 从R和¬R归结
       归结式: NIL（空子句）

结论: 子句集S不可满足
```

**示例2：多文字归结**

**子句集：**
```
S = {P ∨ Q ∨ R, ¬P ∨ S, ¬Q ∨ T, ¬R ∨ ¬S ∨ ¬T}
```

**归结过程：**
```
步骤1: 从P ∨ Q ∨ R和¬P ∨ S归结
       归结式: Q ∨ R ∨ S

步骤2: 从Q ∨ R ∨ S和¬Q ∨ T归结
       归结式: R ∨ S ∨ T

步骤3: 从R ∨ S ∨ T和¬R ∨ ¬S ∨ ¬T归结
       归结式: S ∨ T ∨ ¬S ∨ ¬T

步骤4: 对S ∨ T ∨ ¬S ∨ ¬T进行内部归结
       从S和¬S归结: T ∨ ¬T
       从T和¬T归结: NIL

结论: 子句集S不可满足
```

### 2.3 谓词逻辑中的归结原理

#### 2.3.1 合一（Unification）

**合一的概念：**
- 合一是寻找一个置换，使多个原子公式成为相同公式的过程

**置换（Substitution）：**
- 用项（常量、变量、函数）替换变量的操作
- 记为：σ = {t1/x1, t2/x2, ..., tn/xn}
- 其中ti是项，xi是变量

**示例：**
```
置换σ = {a/x, f(b)/y}
P(x, y)经过σ后变为P(a, f(b))
```

**合一置换：**
- 如果公式集{E1, E2, ..., En}经过置换σ后都成为相同的公式Eσ
- 则称σ为{E1, E2, ..., En}的合一置换

**最一般合一（Most General Unification, MGU）：**
- 在所有合一置换中，最一般的是对变量限制最少的置换
- 记为mgu

**示例：**
```
公式集: {P(x, a), P(b, y)}
合一置换: σ1 = {b/x, a/y}  （得到P(b, a)）
最一般合一: σ2 = {b/x, a/y}  （与σ1相同）

公式集: {P(x, f(y)), P(z, f(g(a)))}
最一般合一: σ = {z/x, g(a)/y}
得到: P(z, f(g(a)))
```

#### 2.3.2 二元归结式的定义

**定义：**
设C1和C2是没有相同变元的两个子句，L1和L2分别是C1和C2中的文字。若σ是{L1, ¬L2}的最一般合一，则称C12为C1和C2的二元归结式。

**说明：**
1. C1和C2不能有相同的变元（如果相同，需要先进行变量标准化）
2. L1和¬L2必须能够合一
3. 归结式是消去L1和L2后，对剩余部分进行析取，并应用合一置换σ

#### 2.3.3 谓词逻辑归结的步骤

**步骤1：变量标准化**
- 确保两个子句没有相同的变量名
- 如果有，需要对其中一个子句的变量进行改名

**步骤2：寻找互补文字对**
- 在两个子句中寻找可以互补的文字对
- 即L1和L2，使得L1和¬L2可以合一

**步骤3：计算最一般合一**
- 计算L1和¬L2的最一般合一置换σ

**步骤4：生成归结式**
- 从两个子句中消去L1和L2
- 对剩余文字进行析取
- 应用合一置换σ

#### 2.3.4 谓词逻辑归结的示例

**示例1：简单谓词归结**

**子句集：**
```
S = {P(x) ∨ Q(x), ¬P(a) ∨ R(a), ¬Q(b)}
```

**归结过程：**
```
步骤1: 从P(x) ∨ Q(x)和¬P(a) ∨ R(a)归结
       互补文字对: P(x)和¬P(a)
       最一般合一: σ = {a/x}
       归结式: Q(a) ∨ R(a)

步骤2: 从Q(a) ∨ R(a)和¬Q(b)归结
       互补文字对: Q(a)和¬Q(b)
       无法合一（a ≠ b）
       归结失败

结论: 无法归结出空子句
```

**示例2：复杂谓词归结**

**子句集：**
```
S = {P(x) ∨ Q(f(x)), ¬P(a) ∨ R(y), ¬Q(f(a)) ∨ ¬R(b)}
```

**归结过程：**
```
步骤1: 从P(x) ∨ Q(f(x))和¬P(a) ∨ R(y)归结
       互补文字对: P(x)和¬P(a)
       最一般合一: σ1 = {a/x}
       归结式: Q(f(a)) ∨ R(y)

步骤2: 从Q(f(a)) ∨ R(y)和¬Q(f(a)) ∨ ¬R(b)归结
       互补文字对: Q(f(a))和¬Q(f(a))
       最一般合一: σ2 = {}
       归结式: R(y) ∨ ¬R(b)

步骤3: 对R(y) ∨ ¬R(b)进行内部归结
       互补文字对: R(y)和¬R(b)
       最一般合一: σ3 = {b/y}
       归结式: NIL

结论: 子句集S不可满足
```

**示例3：函数嵌套的归结**

**子句集：**
```
S = {P(f(x), g(y)), ¬P(f(a), z) ∨ Q(z), ¬Q(g(b))}
```

**归结过程：**
```
步骤1: 从P(f(x), g(y))和¬P(f(a), z) ∨ Q(z)归结
       互补文字对: P(f(x), g(y))和¬P(f(a), z)
       最一般合一: σ1 = {a/x, g(y)/z}
       归结式: Q(g(y))

步骤2: 从Q(g(y))和¬Q(g(b))归结
       互补文字对: Q(g(y))和¬Q(g(b))
       最一般合一: σ2 = {b/y}
       归结式: NIL

结论: 子句集S不可满足
```

### 2.4 归结策略

#### 2.4.1 归结策略的必要性

**问题：**
- 盲目地进行归结会产生大量的冗余子句
- 可能导致组合爆炸
- 影响推理效率

**目的：**
- 减少不必要的归结
- 提高推理效率
- 保证完备性

#### 2.4.2 常见的归结策略

**1. 支持集策略（Set of Support Strategy）**

**基本思想：**
- 选定一个子句集作为支持集
- 归结时至少有一个亲本子句在支持集中
- 支持集通常包含否定目标子句

**优点：**
- 减少冗余归结
- 保证完备性

**示例：**
```
子句集: {P ∨ Q, ¬P ∨ R, ¬Q ∨ R, ¬R}
支持集: {¬R}
归结时至少有一个亲本子句是¬R
```

**2. 线性归结策略（Linear Resolution）**

**基本思想：**
- 从中心子句出发
- 每次归结都使用前一次的归结式
- 形成线性的归结序列

**优点：**
- 归结序列清晰
- 适合实现

**示例：**
```
中心子句: C1
C1与C2归结得到C3
C3与C4归结得到C5
C5与C6归结得到NIL
```

**3. 输入归结策略（Input Resolution）**

**基本思想：**
- 每次归结时至少有一个亲本子句是原始输入子句
- 即来自原子句集的子句

**优点：**
- 简单易实现
- 适合某些应用

**缺点：**
- 不完备（可能找不到解）

**4. 单元归结策略（Unit Resolution）**

**基本思想：**
- 每次归结时至少有一个亲本子句是单元子句
- 单元子句是只包含一个文字的子句

**优点：**
- 效率高
- 适合Horn子句集

**缺点：**
- 不完备

**5. 有序归结策略（Ordered Resolution）**

**基本思想：**
- 对子句中的文字进行排序
- 按照一定的顺序进行归结
- 避免重复计算

**优点：**
- 减少冗余
- 提高效率

### 2.5 归结原理的应用

#### 2.5.1 自动定理证明

**应用场景：**
- 数学定理的自动证明
- 程序正确性验证
- 逻辑推理系统

**实现步骤：**
1. 将定理的前提和结论表示为谓词公式
2. 将结论取反
3. 将所有公式化为子句集
4. 应用归结原理
5. 如果归结出空子句，则定理得证

#### 2.5.2 逻辑程序设计

**应用场景：**
- Prolog语言
- 逻辑编程
- 知识表示和推理

**特点：**
- 基于Horn子句
- 采用SLD归结策略
- 支持回溯和递归

#### 2.5.3 专家系统

**应用场景：**
- 逻辑推理专家系统
- 知识库推理
- 决策支持系统

**优势：**
- 逻辑严密
- 推理过程可追溯
- 适合符号推理

## 归结反演

### 3.1 归结反演的概述

#### 3.1.1 归结反演的定义

**归结反演（Resolution Refutation）：**
- 基于反证法的推理方法
- 通过证明"前提∧¬结论"不可满足，来证明"前提⇒结论"成立
- 利用归结原理进行自动推理

#### 3.1.2 归结反演的理论基础

**反证法：**
- 要证明"前提⇒结论"成立
- 假设"前提"为真，"结论"为假
- 如果导致矛盾，则"结论"必然为真

**逻辑等价性：**
```
前提 ⇒ 结论  等价于  ¬(前提 ∧ ¬结论)
```

**归结原理的作用：**
- 通过归结，检查"前提∧¬结论"是否不可满足
- 如果归结出空子句，说明存在矛盾
- 从而证明"前提⇒结论"成立

### 3.2 归结反演的步骤

#### 步骤1：将已知前提表示为谓词公式F

**要求：**
- 用谓词逻辑表示所有已知前提
- 每个前提可以是一个或多个谓词公式
- 确保公式的正确性和完整性

**示例：**
```
前提1: 所有的人都会死
表示: (∀x)(Person(x) → Mortal(x))

前提2: 苏格拉底是人
表示: Person(Socrates)
```

#### 步骤2：将待证明的结论表示为谓词公式Q，并否定得到¬Q

**要求：**
- 用谓词逻辑表示待证明的结论
- 对结论进行否定
- 确保否定的正确性

**示例：**
```
结论: 苏格拉底会死
表示: Mortal(Socrates)
否定: ¬Mortal(Socrates)
```

#### 步骤3：把谓词公式集{F，¬Q}化为子句集S

**要求：**
- 将所有前提公式和否定后的结论公式分别化为子句集
- 合并所有子句，形成统一的子句集S
- 确保转化过程的正确性

**示例：**
```
前提1: (∀x)(Person(x) → Mortal(x))
转化为子句集: {¬Person(x) ∨ Mortal(x)}

前提2: Person(Socrates)
转化为子句集: {Person(Socrates)}

结论否定: ¬Mortal(Socrates)
转化为子句集: {¬Mortal(Socrates)}

合并子句集S: {¬Person(x) ∨ Mortal(x), Person(Socrates), ¬Mortal(Socrates)}
```

#### 步骤4：应用归结原理对子句集S中的子句进行归结

**要求：**
- 选择合适的子句进行归结
- 应用最一般合一
- 生成新的子句
- 将新子句加入子句集

**示例（继续上面的例子）：**
```
步骤4.1: 从¬Person(x) ∨ Mortal(x)和Person(Socrates)归结
         最一般合一: σ = {Socrates/x}
         归结式: Mortal(Socrates)

步骤4.2: 从Mortal(Socrates)和¬Mortal(Socrates)归结
         归结式: NIL（空子句）
```

#### 步骤5：若出现了空子句，则停止归结，此时就证明了Q为真

**说明：**
- 空子句表示矛盾
- 矛盾说明假设"¬Q"为假
- 因此"Q"为真
- 结论得证

### 3.3 归结反演的完整示例

#### 示例1：简单的三段论推理

**问题：**
证明：如果所有的人都会死，苏格拉底是人，那么苏格拉底会死。

**步骤1：表示前提**
```
前提1: (∀x)(Person(x) → Mortal(x))
前提2: Person(Socrates)
```

**步骤2：表示结论并否定**
```
结论: Mortal(Socrates)
否定: ¬Mortal(Socrates)
```

**步骤3：化为子句集**
```
前提1: ¬Person(x) ∨ Mortal(x)
前提2: Person(Socrates)
结论否定: ¬Mortal(Socrates)

子句集S = {¬Person(x) ∨ Mortal(x), Person(Socrates), ¬Mortal(Socrates)}
```

**步骤4：进行归结**
```
归结1: ¬Person(x) ∨ Mortal(x) 和 Person(Socrates)
       最一般合一: σ = {Socrates/x}
       归结式: Mortal(Socrates)

归结2: Mortal(Socrates) 和 ¬Mortal(Socrates)
       归结式: NIL
```

**步骤5：得出结论**
```
出现了空子句，证明了Mortal(Socrates)为真
```

### 3.4 归结反演的应用

#### 3.4.1 应用归结反演求解问题

**问题描述：**
不仅证明结论为真，还要求出具体的答案。

**步骤：**
1. 已知前提F用谓词公式表示，并化为子句集S
2. 把待求解的问题Q用谓词公式表示，并否定Q，再与ANSWER构成析取式（¬Q ∨ ANSWER）

4. 对S'应用归结原理进行归结
5. 若得到归结式ANSWER，则答案就在ANSWER中

**问题：**
已知：
- 张三的父亲是李四
- 李四的父亲是王五
求：张三的祖父是谁？

```

```
问题: (∃x)Grandfather(x, ZhangSan)
否定: ¬(∃x)Grandfather(x,ZhangSan) = (∀x)¬Grandfather(x, ZhangSan)
加入ANSWER: ¬Grandfather(x, ZhangSan) ∨ ANSWER(x)
```

**明式：**
```
前提1: Father(LiSi, ZhangSan)
前提2: Father(WangWu, LiSi)
前提3: ¬Father(y, x) ∨ ¬Father(z, y) ∨ Grandfather(z, x)
问题子句: ¬Grandfather(x, ZhangSan) ∨ ANSWER(x)

  ¬Grandfather(x,  ZhangSan) ∨ ANSWER(x)
}
```

**步骤4：进行归结**
```
归结1: ¬Father(y, x) ∨ ¬Father(z, y) ∨ Grandfather(z, x) 和 Father(LiSi, ZhangSan)
       最一般合一: σ = {LiSi/y, ZhangSan/x}

归结2: ¬Father(z, LiSi) ∨ 者Grandfather(z, ZhangSan) 和 Father(WangWu, LiSi)

归结3: Grandfather(Wang(x, ZhangSan) 和 ¬Grandfather(x, ZhangSan) ∨ ANSWER(x)

## 可信度方法

### 4.1 可信度方法的概述

#### 4.1.1 可信度方法的历史背景

**提出时间：** 20世纪70年代
**提出者：** 斯坦福大学的Shortliffe等人
**应用系统：** MYCIN血液感染病诊断专家系统
**历史意义：**
- 首次成功应用可信度方法进行不确定性推理
- 为不确定性推理提供了实用方法
- 影响了后续的专家系统开发

#### 4.1.2 可信度的定义

**可信度（Certainty Factor）：**
- 根据经验对一个事物或现象为真的相信程度
- 带有较大的主观性和经验性
- 是对不确定性的一种度量

**特点：**
1. **主观性：** 基于专家的经验和判断
2. **经验性：** 反映了长期实践积累的知识
3. **相对性：** 相对于某个参考标准
4. **可量化：** 可以用数值表示

#### 4.1.3 C-F模型

**C-F模型：**
- 基于可信度表示的不确定性推理的基本方法
- 由可信度因子（Certainty Factor）构成
- 是MYCIN系统的核心推理机制

**基本思想：**
- 用可信度因子表示知识和证据的不确定性
- 通过可信度的传递和组合进行推理
- 最终结论的可信度反映推理的确定性程度

### 4.2 知识不确定性的表示

#### 4.2.1 产生式规则表示

**基本形式：**
```
IF E THEN H (CF(H, E))
```

**说明：**
- E：前提条件（证据）
- H：结论（假设）
- CF(H, E)：可信度因子，反映前提条件与结论的联系强度

#### 4.2.2 可信度因子CF(H, E)的含义

**定义：**
CF(H, P)表示证据E为真时，对结论H的支持程度。

**取值范围：**
```
CF(H, E) ∈ [-1, 1]
```

**取值含义：**
- CF(H, E) = 1：证据E绝对支持结论H
- CF(H, E) = -1：证据E绝对否定结论H
- 0 < CF(H, C) < 1：证据E支持结论H，但不绝对
- -1 < CF(H, E) < 0：证据E否定结论H，但不绝对
- CF(H, E) = 0：证据E与结论H无关

#### 4.2.3 可信度因子的计算

**原始定义：**
```
CF(H, E) = MB(H, E) - MD(H, E)
```

**其中：**
- MB（Measure Belief）：信任增长度量，表示证据E对结论H的支持程度
- MD（Measure Disbelief）：不信任增长度量，表示证据E对结论H的否定程度

**计算公式：**
```
MB(H, E) = 
  1, 如果 P(H) = 1
  (P(H|E) - P(H)) / (1 - P(H)), 如果 P(H) < 1

MD(H, E) = 
  1, 如果 P(H) = 0
  (P(H) - P(H|E)) / P(H), 如果 P(H) > 0
```

**简化理解：**
- CF(H, E) > 0：证据E支持结论H
- CF(H, E) < 0：证据E否定结论H
- CF(H, E) = 0：证据E与结论H无关

### 4.3 证据不确定性的表示

#### 4.1 证据的可信度

**定义：**
证据E的可信度CF(E)表示证据E为真的可信程度。

**取值范围：**
```
CF(E) ∈ [-1, 1]
```

**取值含义：**
- CF(E) = 1：证据E肯定为真
- CF(E) = -1：证据E肯定为假
- 0 < CF(E) < 1：证据E以某种程度为真
- -1 < CF(E) < 0：证据E以某种程度为假
- CF(E) = 0：未获得任何相关的观察

#### 4.3.2 证据可信度的获取

**获取方式：**
1. **直接观察：** 由用户直接输入
2. **推理得到：** 通过推理计算得到
3. **测量得到：** 通过传感器等设备测量

**示例：**
```
证据1: 患者体温38.5℃
CF(体温38.5℃) = 0.95

证据2: 患者咳嗽
CF(咳嗽) = 0.8

证据3: 患者没有胸痛
CF(胸痛) = -0.7
```

### 4.4 组合证据不确定性的算法

#### 4.4.1 组合证据的概念

**组合证据：**
- 多个单一证据通过逻辑运算组合成复合证据
- 常见的逻辑运算：合取（AND）、析取（OR）

#### 4.4.2 合取证据的可信度

**规则：**
```
CF(E) = min{CF(E1), CF(E), …, CF(取最弱的可信度）
```

**示例：**
```
IF 发烧 AND 咳嗽 THEN 肺炎 (CF = 0.8)

CF(发烧) = 0.9
CF(咳嗽) = 0.7

CF(发烧 AND 咳嗽) = min{0.9, 0.7} = 0.7
```

**说明：**
- 合取证据的可信度取所有证据可信度的最小值
- 这是因为合取要求所有条件都满足
- 最弱的条件决定了整体的强度

#### 4.4.3 析取证据的可信度

**规则：**
```
CF(E) = max{CF(E1), CF(E2), …, CF(En)}
```

**示例：```
IF 发烧 OR 咳嗽 THEN 呼吸道感染 (CF = 0.7)

CF(发烧) = 0.9
CF(咳嗽) = 0.7

CF(发烧 OR 咳嗽) = max{0.9, 0.7} = 0.9
```

**说明：**
- 析取证据的可信度取所有证据可信度的最大值
- 这是因为析取只要有一个条件满足即可
- 最强的条件决定了整体的强度

### 4.5 不确定性的传递算法

#### 4.5.1 传递算法的定义

**问题：**
已知证据E的可信度CF(E)和规则的可信度CF(H, E)，如何计算结论H的可信度CF(H)？

#### 4.2 传递算法的公式

**基本公式：**
```
CF(H) = CF(H, E) × max{0, CF(E)}
```

**说明：**
1. 如果CF(E) ≥ 0（证据为真或部分为真）：
   - CF(H) = CF(H, E) × CF(E)
2. 如果CF(E) < 0（证据为假或部分为假）：
   - CF(H) = 0（规则不触发）

#### 4.5.3 传递算法的示例

**示例1：证据为真**
```
规则: IF 发烧 THEN 感冒 (CF = 0.8)

CF(发烧) = 0.9

CF(感冒) = CF(感冒, 发烧) × CF(发烧)
        = 0.8 × 0.9
        = 0.72
```

**示例2：证据部分为真**
```
规则: IF 胸痛 THEN 肺炎 (CF = 0.7)

CF(胸痛) = 0.6

CF(肺炎) = CF(肺炎, 胸痛) × CF()
         = 0.7 × 0.6
         = 0.42
```

**示例3：证据为假**
```
规则: IF 发烧 THEN 感冒 (CF = 0.8)

CF(发烧) = -0.5

CF(感冒) = CF(感冒, 发烧) × max{0, CF(发烧)}
         = 0.8 × 0
         = 0
```

**示例4：证据完全为真**
```
规则: IF 咳嗽 THEN 支气管炎 (CF = 0.9)

CF(咳嗽) = 1.0

CF(支气管炎) = CF(支气管炎, 咳嗽) × CF(咳嗽)
             = 0.9 × 1.0
             = 0.9
```

### 4.6 结论不确定性的合成算法

#### 4.6.1 合成算法的问题

**问题：**
当有多条规则支持同一个结论时，如何综合这些规则的结论？

**示例：**
```
规则1: IF 发烧 THEN 感冒 (CF1 = 0.8)
规则2: IF 咳嗽 THEN 感冒 (CF2 = 0.7)

已知：
CF(发烧) = 0.9
CF(咳嗽) = 0.6

如何计算CF(感冒)？
```

#### 4.6.2 合成算法的步骤

**步骤1：分别对每一条知识求出CF(H)**
```
CF1(H) = CF(H, E1) × max{0, CF(E1)}
CF2(H) = CF(H, E2) × max{0, CF(E2)}
```

**步骤2：计算综合可信度**
```
CF12(H) = 
  if CF1(H) ≥ 0, CF2(H) ≥ 0:
    CF1(H) + CF2(H) - CF1(H) × CF2(H)
  if CF1(H) < 0, CF2(H) < 0:
    CF1(H) + CF2(H) + CF1(H) × CF2(H)
  if CF1(H) × CF(H) < 0:
    CF1(H) + CF2(H)
  if CF1(H) × CF2(H) > 0:
    (CF1(H) + CF2(H)) / (1 - min{|CF1(H)|, |CF2(H)|})
```

#### 4.3 合成算法的详细说明

**情况1：两个可信度都为正（相互支持）**
```
CF12(H) = CF1(H) + CF2(H) - CF1(H) × CF2(H)
```

**说明：**
- 两个可信度都支持结论
- 综合可信度应该比单个可信度高
- 不会超过1

**示例：**
```
CF1(H) = 0.8
CF2(H) = 0.6

CF12(H) = 0.8 + 0.6 - 0.8 × 0.6
        = 1.4 - 0.48
        = 0.92
```

**情况2：两个可信度都为负（相互否定）**
```
CF12(H) = CF1(H) + CF2(H) + CF1(H) × CF2(H)
```

**说明：**
- 两个可信度都否定结论
- 综合可信度应该比单个可信度更低
- 不会低于-1

**示例：**
```
CF1(H) = -0.7
CF2(H) = -0.5

CF12(H) = -0.7 + (-0.5) + (-0.7) × (-0.5)
        = -1.2 + 0.35
        = -0.85
```

**情况3：两个可信度符号相反（相互抵消）**
```
if |CF1(H)| ≤ |CF2|:
  CF12(H) = CF1(H) + CF2(H)

if |CF1(H)| > |CF2(H)|:
  CF12(H) = CF1(H) + CF2(H)
```

**说明：**
- 一个支持，一个否定
- 综合可信度是两者的代数和

**示例：**
```
CF1(H) = 0.8
CF2(H) = -0.3

CF12(H) = 0.8 + (-0.3)
        = 0.5
```

**情况4：两个可信度符号相同但绝对值不同**
```
CF12(H) = (CF1(H) + CF2(H)) / (1 - min{|CF1(H)|, |CF2(H)|})
```

**说明：**
- 这个公式实际上是情况1和情况2的推广
- 当两个可信度符号相同时使用

**示例：**
```
CF1(H) = 0.9
CF2(H) = 0.7

CF12(H) = (0.9 + 0.7) / (1 - min{0.9, 0.7})
        = 1.6 / (1 - 0.7)
        = 1.6 / 0.3
        = 5.33

但CF不能超过1，所以取CF12(H) = 1
```

#### 4.6.4 合成算法的完整示例

**示例：医疗诊断**

**规则库：**
```
规则1: IF 发烧 THEN 感冒 (CF = 0.8)
规则2: IF 咳嗽 THEN 感冒 (CF = 0.7)
规则3: IF 流鼻涕 THEN 感冒 (CF = 0.6)
```

**证据：**
```
CF(发烧) = 0.9
CF(咳嗽) = 0.6
CF(流鼻涕) = 0.8
```

**计算过程：**

**步骤1：分别计算每个规则的结论可信度**
```
CF1(感冒) = CF(感冒, 发烧) × CF(发烧)
         = 0.8 × 0.9
         = 0.72

CF2(感冒) = CF(感冒, 咳嗽) × CF(咳嗽)
         = 0.7 × 0.6
         = 0.42

CF3(感冒) = CF(感冒, 流鼻涕) × CF(CF(流鼻涕)
         = 0.6 × 0.8
         = 0.48
```

**步骤2：综合前两个规则的结论**
```
CF12(感冒) = CF1(感冒) + CF2(感冒) - CF1(感冒) × CF2(感冒)
          = 0.72 + 0.42 - 0.72 × 0.42
          = 1.14 - 0.3024
          = 0.8376
```

**步骤3：综合第三个规则的结论**
```
CF123(感冒) = CF12(感冒) + CF3(感冒) - CF12(感冒) × CF3(感冒)
           = 0.8376 + 0.48 - 0.8376 × 0.48
           = 1.3176 - 0.402
           = 0.9156
```

**最终结论：**
```
CF(感冒) = 0.9156
```

### 4.7 可信度方法的完整推理示例

#### 示例：医疗诊断系统

**问题：**
根据患者的症状，诊断患者是否患有肺炎。

**规则库：**
```
规则1: IF 发烧 AND 咳嗽 THEN 肺炎 (CF = 0.8)
规则2: IF 胸痛 AND 呼吸困难 THEN 肺炎 (CF = 0.9)
规则3: IF 发烧 AND 胸痛 THEN 肺炎 (CF = 0.7)
```

**证据：**
```
CF(发烧) = 0.9
CF(咳嗽) = 0.7
CF(胸痛) = 0.8
CF(呼吸困难) = 0.6
```

**推理过程：**

**步骤1：计算规则1的结论**
```
CF(发烧 AND 咳嗽) = min{CF(发烧), CF(咳嗽)}
                   = min{0.9, 0.7}
                   = 0.7

CF1(肺炎) = CF(肺炎, 发烧 AND 咳嗽) × CF(发烧 AND 咳嗽)
         = 0.8 × 0.7
         = 0.56
```

**步骤2：计算规则2的结论**
```
CF(胸痛 AND 呼吸困难) = min{CF(胸痛), CF(呼吸困难)}
                      = min{0.8, 0.6}
                      = 0.6

CF2(肺炎) = CF(肺炎, 胸痛 AND 呼吸困难) × CF(胸痛 AND 呼吸困难)
         = 0.9 × 0.6
         = 0.
```

**步骤3：计算规则3的结论**
```
CF(发烧 AND 胸痛) = min{CF(发烧), CF(胸痛)}
                   = min{0.9, 0.8}
                   = 0.8

CF3(肺炎) = CF(肺炎, 发烧 AND 胸痛) × CF(发烧 AND 胸痛)
         = 0.7 × 0.8
         = 0.56
```

**步骤4：综合所有规则的结论**

**先综合CF1和CF2：**
```
CF12(肺炎) = CF1(肺炎) + CF2(肺炎) - CF1(肺炎) × CF2(肺炎)
          = 0.56 + 0.54 - 0.56 × 0.54
          = 1.1 - 0.3024
          = 0.7976
```

**再综合CF12和CF3：**
```
CF123(肺炎) = CF12(肺炎) + CF3(肺炎) - CF12(肺炎) × CF3(肺炎)
           = 0.7976 + 0.56 - 0.7976 × 0.56
           = 1.3576 - 0.446656
           = 0.910944
```

**最终结论：**
```
CF(肺炎) = 0.91
```

**诊断结果：**
患者患有肺炎的可信度为0.91，说明患者很可能患有肺炎。

### 4.8 可信度方法的特点

#### 4.8.1 优点

1. **简单性：**
   - 计算公式简单
   - 易于理解和实现
   - 适合实际应用

2. **直观性：**
   - 可信度概念直观
   - 符合人类思维习惯
   - 便于专家提供知识

3. **实用性：**
   - 在MYCIN等系统中成功应用
   - 适合不确定性推理
   - 效果良好

4. **灵活性：**
   - 可以处理各种不确定性
   - 可以组合多个证据
   - 可以传递不确定性

#### 4.8.2 缺点

1. **主观性：**
   - 可信度因子的确定依赖专家经验
   - 不同专家可能给出不同的值
   - 缺乏客观标准

2. **理论基础：**
   - 缺乏严格的数学基础
   - 与概率论的关系不明确
   - 某些情况下可能不合理

3. **组合问题：**
   - 多个证据组合时可能出现问题
   - 合成算法有时会产生不合理结果
   - 需要仔细设计

4. **独立性假设：**
   - 假设证据之间相互独立
- 实际中证据可能相关
- 需要考虑证据的相关性

#### 4.8.3 适用场景

**适合应用可信度方法的场景：**
1. 知识主要来自专家经验
2. 缺乏统计数据
3. 不确定性的表示和推理是必要的
4. 需要简单直观的方法

**典型应用领域：**
1. 医疗诊断
2. 故障诊断
3. 决策支持
4. 专家系统

### 4.9 可信度方法与其他方法的比较

#### 4.9.1 与概率论的比较

**概率论：**
- 有严格的数学基础
- 要求统计数据
- 计算复杂

**可信度方法：**
- 理论基础较弱
- 基于专家经验
- 计算简单

**选择：**
- 如果有统计数据，优先使用概率论
- 如果缺乏统计数据，使用可信度方法

#### 4.9.2 与证据理论的比较

**证据理论（D-S理论）：**
- 可以处理不知道的情况
- 计算复杂
- 理论基础较好

**可信度方法：**
- 不能明确表示不知道
- 计算简单
- 理论基础较弱

**选择：**
- 如果需要表示不知道，使用证据理论
- 如果需要简单方法，使用可信度方法

#### 4.9.3 与模糊逻辑的比较

**模糊逻辑：**
- 处理模糊性
- 适合连续值
- 理论基础较好

**可信度方法：**
- 处理不确定性
- 适合离散值
- 理论论基础较弱

**选择：**
- 如果处理模糊性，使用模糊逻辑
- 如果处理不确定性，使用可信度方法
