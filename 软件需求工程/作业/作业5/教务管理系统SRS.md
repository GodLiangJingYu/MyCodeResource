## 1 引言

### 1.1 编写目的

本 SRS 文档定义教务管理系统的功能、性能和界面需求，作为开发、测试及验收的基准。

### 1.2 项目背景

高校教务管理工作量大，传统人工模式效率低且易出错。本系统采用三层 B/S 架构，旨在提高管理效率，实现学生选课、成绩管理及教师信息维护的数字化，淘汰传统管理模式。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| SRS | 软件需求规格说明书 |
| B/S | 浏览器/服务器架构 |
| 三层架构 | 表现层、业务逻辑层、数据访问层 |
| 选课 | 学生在规定时间内选定课程 |
| 退课 | 学生取消已选课程 |
| 管理员 | 系统最高权限用户 |

### 1.4 参考资料

- GB/T 9385-2008 计算机软件需求规格说明规范
- 《软件需求工程》课程要求

## 2 总体描述

### 2.1 产品概述

教务管理系统是基于 Web 的管理平台，采用三层 B/S 架构。管理员、教师和学生通过浏览器访问系统网址，登录后使用各自权限内的功能。

### 2.2 产品功能概要

系统功能按角色划分：

| 角色 | 功能模块 |
|------|---------|
| 学生 | 登录、选课、退课、查询课程、查询成绩（按学年/排序）、修改密码 |
| 教师 | 登录、查询/修改个人信息、查询学生信息、录入成绩、打印信息 |
| 管理员 | 登录、管理学生/教师/自身数据、维护系统数据库 |

### 2.3 用户特征

- **学生**：主要进行数据查询、选课、退课及密码修改。
- **教师**：负责个人信息维护、学生信息查询、成绩录入及打印。
- **管理员**：拥有最高权限，负责数据库更新及各类基础数据管理。

### 2.4 运行环境

| 项目 | 说明 |
|------|------|
| 客户端 | 主流浏览器（Chrome、Firefox、Edge 等） |
| 应用服务器 | 支持 Java/Python/.NET 等 Web 应用框架的服务器 |
| 数据库服务器 | MySQL / SQL Server / Oracle 等关系型数据库 |
| 网络环境 | 校园局域网或互联网 |

### 2.5 约束条件

1. 系统必须采用三层 B/S 架构。
2. 系统必须支持三种角色（学生、教师、管理员）的身份认证和权限控制。
3. 系统需在校园网络环境下稳定运行。
4. 系统应符合高校现有的教务管理业务流程。

### 2.6 假设与依赖

1. 假设学校已有稳定的校园网络基础设施。
2. 假设用户已分配初始账户和密码。
3. 假设相关课程数据、学生数据、教师数据已由管理员预先录入系统。
4. 系统依赖关系型数据库提供数据存储服务。

## 3 外部接口需求

### 3.1 用户界面

1. 系统提供统一的 Web 登录页面，包含账户输入框、密码输入框和角色选择项（学生/教师/管理员）。
2. 登录成功后，根据用户角色显示相应的功能菜单主页面。
3. 界面设计简洁直观，符合 Web 应用操作习惯。
4. 各功能模块通过导航菜单切换。
5. 查询结果以表格形式展示，支持分页。
6. 打印功能提供预览界面。

### 3.2 硬件接口

1. 客户端：支持标准键盘、鼠标输入设备以及显示器输出。
2. 服务器端：标准的网络接口（以太网）。
3. 打印机接口：通过浏览器调用本地打印机实现打印功能。

### 3.3 软件接口

1. **操作系统**：服务器端支持 Windows Server / Linux；客户端支持 Windows、macOS、Linux。
2. **数据库**：系统通过 JDBC/ODBC 等标准接口与关系型数据库进行通信。
3. **浏览器**：支持 HTML5、CSS3、JavaScript 标准的主流浏览器。

### 3.4 通信接口

1. 系统使用 HTTP/HTTPS 协议进行客户端与服务器之间的通信。
2. 系统采用 TCP/IP 协议栈进行网络数据传输。
3. 应用服务器与数据库服务器之间通过数据库专用协议通信。

## 4 功能需求

### 4.1 登录模块

#### 4.1.1 用户登录（FR-LOGIN-001）

**描述**：用户访问登录页面，输入账户、密码并选择身份角色后登录。

**参与者**：学生、教师、管理员

**前置条件**：用户已被分配初始账户和密码。

**基本流程**：

1. 用户打开系统网址，进入登录页面。
2. 用户输入账户名。
3. 用户输入密码。
4. 用户选择身份角色（学生 / 教师 / 管理员）。
5. 用户点击“登录”按钮。
6. 系统验证账户、密码及角色是否匹配。
7. 验证通过，进入对应角色的主页面。


**备选流程**：

- 6a. 账户或密码错误：系统提示"账户或密码错误，请重新输入"，返回步骤2。
- 6b. 角色选择不匹配：系统提示"身份选择错误"，返回步骤4。

**后置条件**：用户成功登录并进入对应角色的功能主页面。

### 4.2 学生功能模块

#### 4.2.1 查询课程（FR-STU-001）

**描述**：学生查询当前可选的课程信息。

**参与者**：学生

**前置条件**：学生已成功以"学生"身份登录系统。

**基本流程**：

1. 学生进入"查询课程"功能页面。
2. 学生可设置查询条件（如课程名称、课程编号、授课教师、开课学年等）。
3. 系统根据查询条件从数据库中检索课程数据。
4. 系统以列表形式展示查询结果（包含课程编号、课程名称、学分、授课教师、上课时间等）。

**备选流程**：

- 3a. 无匹配结果：系统提示"未查询到相关课程信息"。

**后置条件**：学生查看到课程信息。

#### 4.2.2 选课（FR-STU-002）

**描述**：学生在相关学年的课程中选定所需课程。

**参与者**：学生

**前置条件**：学生已成功登录；当前处于选课时间段。

**基本流程**：

1. 学生进入“选课”页面。
2. 系统展示当前学年可选课程列表。
3. 学生选定需要的课程。
4. 学生点击“确认选课”按钮。
5. 系统检查课程冲突（时间、人数上限等）。
6. 系统保存选课记录。
7. 系统提示“选课成功”。

**备选流程**：

- 5a. 课程时间冲突：系统提示"所选课程时间与已选课程冲突，请重新选择"。
- 5b. 课程人数已满：系统提示"该课程选课人数已达上限"。

**后置条件**：选课记录成功保存到数据库。

#### 4.2.3 退课（FR-STU-003）

**描述**：学生取消已选定的课程。

**参与者**：学生

**前置条件**：学生已成功登录；学生已有选课记录。

**基本流程**：

1. 学生进入"已选课程"页面。
2. 系统展示学生当前已选课程列表。
3. 学生选择需要退订的课程。
4. 学生点击"退课"按钮。
5. 系统弹出确认提示："确定退选该课程？"
6. 学生确认退课操作。
7. 系统从数据库中删除该选课记录。
8. 系统提示"退课成功"。

**备选流程**：

- 6a. 学生取消操作：返回已选课程页面，不做任何修改。

**后置条件**：选课记录从数据库中移除，课程可选名额恢复。

#### 4.2.4 查询成绩（FR-STU-004）

**描述**：学生根据学年查询自己的课程成绩，并可对成绩进行排序。

**参与者**：学生

**前置条件**：学生已成功登录；相关成绩已由教师录入。

**基本流程**：

1. 学生进入"查询成绩"功能页面。
2. 学生选择查询的学年。
3. 系统从数据库中检索该学生在该学年的所有课程成绩。
4. 系统以列表形式展示成绩（包含课程名称、学分、成绩等）。
5. 学生可选择按成绩升序或降序排序。
6. 系统按照排序条件重新排列并展示成绩列表。

**备选流程**：

- 3a. 该学年暂无成绩记录：系统提示"该学年暂无成绩数据"。

**后置条件**：学生查看到对应学年的成绩信息。

#### 4.2.5 修改密码（FR-STU-005）

**描述**：学生修改自己的登录密码。

**参与者**：学生

**前置条件**：学生已成功登录。

**基本流程**：

1. 学生进入"修改密码"功能页面。
2. 学生输入原密码。
3. 学生输入新密码。
4. 学生再次输入新密码进行确认。
5. 系统验证原密码是否正确。
6. 系统验证两次输入的新密码是否一致。
7. 系统验证新密码是否符合安全要求（长度、复杂度等）。
8. 系统更新数据库中的密码记录。
9. 系统提示"密码修改成功"。

**备选流程**：

- 5a. 原密码错误：系统提示"原密码输入错误"。
- 6a. 两次新密码不一致：系统提示"两次输入的新密码不一致"。
- 7a. 新密码不符合安全要求：系统提示密码安全规则。

**后置条件**：密码更新成功，下次登录需使用新密码。

### 4.3 教师功能模块

#### 4.3.1 查询个人信息（FR-TEA-001）

**描述**：教师查询自己在系统中的个人信息。

**参与者**：教师

**前置条件**：教师已成功以"教师"身份登录系统。

**基本流程**：

1. 教师进入"个人信息"功能页面。
2. 系统从数据库中读取教师的个人信息。
3. 系统展示教师的个人信息，包括：姓名、出生年月、政治面貌、联系电话、联系地址等。

**后置条件**：教师查看到自己的个人信息。

#### 4.3.2 修改个人信息（FR-TEA-002）

**描述**：教师修改自己在系统中的个人信息。

**参与者**：教师

**前置条件**：教师已成功登录。

**基本流程**：

1. 教师进入"个人信息"功能页面。
2. 系统展示教师当前的个人信息。
3. 教师修改需要更新的字段（如联系电话、联系地址、政治面貌等）。
4. 教师点击"保存"按钮。
5. 系统对输入数据进行格式校验。
6. 系统将更新后的信息写入数据库。
7. 系统提示"信息修改成功"。

**备选流程**：

- 5a. 输入数据格式不合法（如电话号码格式错误）：系统提示具体的格式错误信息。

**后置条件**：教师的个人信息在数据库中更新。

#### 4.3.3 查询学生信息（FR-TEA-003）

**描述**：教师查询所带领班级的学生信息。

**参与者**：教师

**前置条件**：教师已成功登录；教师已被分配管理的班级。

**基本流程**：

1. 教师进入"学生信息查询"功能页面。
2. 教师选择要查询的班级。
3. 系统从数据库中检索该班级的学生信息。
4. 系统展示班级信息（班级名称、班级人数）以及学生列表（学生姓名、学号、成绩等）。

**备选流程**：

- 3a. 班级暂无学生数据：系统提示"该班级暂无学生信息"。

**后置条件**：教师查看到所带班级的学生信息。

#### 4.3.4 录入成绩（FR-TEA-004）

**描述**：教师录入所管理班级学生的课程成绩。

**参与者**：教师

**前置条件**：教师已成功登录。

**基本流程**：

1. 教师进入“成绩管理”页面。
2. 教师选择班级和课程。
3. 系统展示选修该课程的学生名单。
4. 教师输入每位学生的成绩。
5. 教师点击“提交成绩”按钮。
6. 系统校验成绩合法性（0-100 分）。
7. 系统保存成绩数据。
8. 系统提示“成绩录入成功”。

**备选流程**：

- 6a. 成绩数据不合法：系统标注不合法的成绩项，提示教师修改。
- 4a. 教师可选择"暂存"功能，保存尚未全部录入的成绩，待后续继续录入。

**后置条件**：学生的课程成绩保存到数据库中。

#### 4.3.5 打印信息（FR-TEA-005）

**描述**：教师打印自己的个人信息或学生的成绩信息。

**参与者**：教师

**前置条件**：教师已成功登录；需要打印的数据已存在于系统中。

**基本流程**：

1. 教师进入"打印"功能页面。
2. 教师选择打印内容类型（个人信息 / 学生成绩）。
3. 若选择"学生成绩"，教师需进一步选择班级和课程。
4. 系统生成打印预览页面。
5. 教师确认打印内容无误后，点击"打印"按钮。
6. 系统调用浏览器打印功能，将内容发送至打印机。

**后置条件**：信息被成功打印输出。

### 4.4 管理员功能模块

#### 4.4.1 管理学生数据（FR-ADM-001）

**描述**：管理员对系统中的学生数据进行增删改查。

**参与者**：管理员

**前置条件**：管理员已成功以"管理员"身份登录系统。

**基本流程**：

1. 管理员进入"学生管理"功能页面。
2. 系统展示学生数据列表，支持搜索和筛选。
3. 管理员可执行以下操作：
   - **新增学生**：输入学生的学号、姓名、性别、班级、联系方式等信息，系统为其生成初始账户和密码，保存至数据库。
   - **修改学生信息**：选择某一学生记录，修改其信息字段，保存更新。
   - **删除学生**：选择某一学生记录，确认后从数据库中删除（或标记为注销）。
   - **查询学生**：通过学号、姓名等条件检索学生信息。
4. 系统执行相应的数据库操作。
5. 系统反馈操作结果。

**备选流程**：

- 3a. 新增时学号已存在：系统提示"该学号已存在，请确认"。
- 3c. 删除时弹出确认对话框，管理员取消则不执行删除。

**后置条件**：学生数据在数据库中更新。

#### 4.4.2 管理教师数据（FR-ADM-002）

**描述**：管理员对系统中的教师数据进行增删改查。

**参与者**：管理员

**前置条件**：管理员已成功登录。

**基本流程**：

1. 管理员进入"教师管理"功能页面。
2. 系统展示教师数据列表，支持搜索和筛选。
3. 管理员可执行以下操作：
   - **新增教师**：输入教师的工号、姓名、出生年月、政治面貌、联系电话、联系地址等信息，系统为其生成初始账户和密码，保存至数据库。
   - **修改教师信息**：选择某一教师记录，修改其信息字段，保存更新。
   - **删除教师**：选择某一教师记录，确认后从数据库中删除（或标记为注销）。
   - **查询教师**：通过工号、姓名等条件检索教师信息。
4. 系统执行相应的数据库操作。
5. 系统反馈操作结果。

**后置条件**：教师数据在数据库中更新。

#### 4.4.3 管理管理员自身数据（FR-ADM-003）

**描述**：管理员更新自己的个人信息，如姓名、联系方式等。

**参与者**：管理员

**前置条件**：管理员已成功登录。

**基本流程**：

1. 管理员进入"个人设置"功能页面。
2. 系统展示管理员当前的个人信息。
3. 管理员修改需要更新的字段（如姓名、联系方式等）。
4. 管理员点击"保存"按钮。
5. 系统对输入数据进行校验。
6. 系统将更新后的信息写入数据库。
7. 系统提示"信息修改成功"。

**后置条件**：管理员个人信息在数据库中更新。

#### 4.4.4 维护系统数据库（FR-ADM-004）

**描述**：管理员根据实时信息，更新教务管理系统的数据库。

**参与者**：管理员

**前置条件**：管理员已成功登录。

**基本流程**：

1. 管理员录入或更新课程、班级、学年等基础数据。
2. 管理员设置选课时间、成绩录入时间等系统参数。
3. 系统校验并保存数据。
4. 系统提示操作结果。

**后置条件**：系统基础数据更新完成。

## 5 非功能需求

### 5.1 性能需求

| 编号 | 需求描述 |
|------|---------|
| NFR-001 | 系统应支持至少 500 个用户同时在线访问 |
| NFR-002 | 页面加载时间不超过 3 秒（校园网环境下） |
| NFR-003 | 选课高峰期系统响应时间不超过 5 秒 |
| NFR-004 | 数据库查询操作响应时间不超过 2 秒 |

### 5.2 安全性需求

| 编号 | 需求描述 |
|------|---------|
| NFR-005 | 用户密码必须加密存储，不得以明文形式保存 |
| NFR-006 | 系统必须实现基于角色的访问控制（RBAC），不同角色只能访问其权限范围内的功能 |
| NFR-007 | 登录失败超过 5 次后，账户应被临时锁定 |
| NFR-008 | 用户会话超时（如 30 分钟无操作）后应自动退出登录 |
| NFR-009 | 系统应防止 SQL 注入、XSS 等常见 Web 安全攻击 |

### 5.3 可靠性需求

| 编号 | 需求描述 |
|------|---------|

## 6 其他需求

### 6.1 数据需求

#### 6.1.1 数据实体

系统涉及的主要数据实体及其核心属性如下：

| 数据实体 | 核心属性 |
|---------|---------|
| 学生 | 学号、姓名、性别、班级、账户、密码、联系方式 |
| 教师 | 工号、姓名、出生年月、政治面貌、联系电话、联系地址、账户、密码 |
| 管理员 | 管理员编号、姓名、联系方式、账户、密码 |
| 课程 | 课程编号、课程名称、学分、授课教师、上课时间、最大选课人数 |
| 选课记录 | 学生学号、课程编号、选课学年 |
| 成绩 | 学生学号、课程编号、学年、成绩分数 |
| 班级 | 班级编号、班级名称、所属专业、班级人数 |

#### 6.1.2 数据关系

- 一名学生属于一个班级（多对一）。
- 一名教师可带领多个班级（一对多）。
- 一名学生可选修多门课程，一门课程可被多名学生选修（多对多，通过选课记录关联）。
- 一门课程由一名教师讲授（多对一）。
- 一条成绩记录对应一名学生的一门课程在某学年的成绩。

### 6.2 运行需求

- 系统需 7×24 小时不间断运行。
- 系统应具备基本的容错能力，单点故障不应导致整体服务不可用。
