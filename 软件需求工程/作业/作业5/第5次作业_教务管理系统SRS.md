# 教务管理系统软件需求规格说明书（SRS）

**文档编号**：EMS-SRS-001  
**版本**：V1.0  
**编制日期**：2024年4月

---

## 1. 引言

### 1.1 编写目的

本文档旨在详细、完整地描述"教务管理系统"的软件需求规格，对系统应实现的全部功能需求、性能需求、接口需求以及其他非功能性属性进行明确说明。本文档是系统设计、编码实现、测试验证和用户验收的唯一需求依据。

本文档的预期读者包括：
- 软件开发工程师（了解系统须实现的功能边界和业务规则）
- 软件测试工程师（以此为基础设计测试用例和验收标准）
- 项目经理（掌握项目范围，辅助任务分解与排期）
- 高校教务处负责人（业务方，确认系统满足实际管理需求）

### 1.2 项目背景

随着高校招生规模持续扩大，学生人数增多，课程体系日趋复杂，传统依赖纸质表格、人工统计的教务管理模式已无法满足效率和准确性的要求。本项目由某高校教务处委托开发，旨在构建一套现代化、网络化的教务管理平台，采用三层B/S（浏览器/服务器）架构，通过角色权限划分，为管理员、教师和学生提供差异化的功能访问入口，全面淘汰传统手工管理模式，显著提升教务工作效率和数据准确性。

### 1.3 定义与缩写

| 术语 | 定义 |
|---|---|
| SRS | Software Requirements Specification，软件需求规格说明书 |
| B/S架构 | Browser/Server，浏览器/服务器架构，客户端仅需浏览器即可访问系统 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
| FR | Functional Requirement，功能性需求 |
| NFR | Non-Functional Requirement，非功能性需求 |
| 学年 | 一个完整教学年度，如2023-2024学年 |

### 1.5 假设与依赖

1. **假设**：本系统假设全校师生均已由管理员完成初始账号创建和密码分配，学生和教师无法自行注册账号。
2. **假设**：所有用户可访问稳定的校园局域网或互联网，网络环境满足正常Web访问需求。
3. **依赖**：本系统的选课、成绩等数据的合法性依赖学校课程计划数据的预先录入，开学前管理员须初始化课程数据。
4. **依赖**：打印功能依赖客户端机器已安装合法可用的打印驱动程序，或浏览器支持调用本地打印机服务。

## 2. 总体描述

### 2.1 产品前景

本系统是一个面向全校师生及教务管理人员的独立Web应用系统，不与其他第三方系统进行直接集成。系统的核心价值在于：
- 为学生提供**在线选课与成绩自查**的便利渠道，减少到教务处排队办理的人力和时间成本。
- 为教师提供**成绩录入与学生信息查阅**的统一入口，避免纸质表格丢失或数据错误。
- 为管理员提供**全局数据维护**的管理后台，实现对全校教学数据的集中管控。

### 2.2 产品功能概述

本系统按照用户角色划分为三大子系统：

| 子系统名称 | 核心功能 |
|---|---|
| 学生子系统 | 登录、课程查询、选课、退课、成绩查询（含排序）、密码修改 |
| 教师子系统 | 登录、个人信息查询与修改、学生信息查询、成绩录入、信息打印 |
| 管理员子系统 | 登录、学生信息管理（增删改查）、教师信息管理（增删改查）、自身信息维护 |

### 2.3 用户特征

**（1）学生**  
学生是系统访问量最大的用户群体，数量通常超过全校在校生总数。学生的计算机操作能力参差不齐，系统界面须足够直观，以保证学生无需培训即可自主完成选课等核心操作。学生的主要使用高峰期集中在学期初的选课周及期末的成绩查询期，对系统并发承载能力有较高要求。

**（2）教师**  
教师群体具备基本的计算机操作能力。其主要使用场景集中在期末成绩录入阶段，使用频率相对较低但操作准确性要求极高，一旦成绩录入错误将直接影响学生的学业记录。

**（3）管理员**  
管理员是高校教务处的工作人员，具有较高的计算机操作能力和丰富的业务处理经验。管理员拥有系统最高权限，日常负责系统基础数据的更新与维护，使用频率稳定但操作影响范围最广。

### 2.4 运行环境

- **客户端**：支持主流现代Web浏览器，包括Chrome 80+、Firefox 75+、Edge 80+、Safari 13+；无需安装任何插件或客户端软件。
- **服务器端**：部署于Linux操作系统的应用服务器；使用MySQL 8.0或Oracle 19c及以上版本的关系型数据库。
- **网络环境**：校园局域网或互联网，推荐带宽≥10Mbps。

## 3. 具体需求

### 3.1 外部接口需求

**（1）用户接口**  
- 登录页须提供清晰的"角色选择"控件（下拉框或单选按钮），学生/教师/管理员在同一页面完成角色选择后再进行身份验证。
- 系统全程采用中文界面，关键操作须有二次确认弹窗（如退课、删除信息等不可逆操作）。

**（2）数据接口**  
- 系统数据存储于关系型数据库，表间通过外键维护完整性约束；前后端通过HTTP/HTTPS协议交互，数据格式为JSON。

### 3.2 功能需求

#### 3.2.1 学生端功能需求（FR-STU）

**FR-STU-001：学生登录**
- **描述**：学生在登录页输入账号、密码并选择"学生"角色，提交后由系统进行身份验证，验证通过则进入学生功能主界面。
- **前置条件**：学生已由管理员创建账号并获知初始密码。
- **输入**：账号（学号）、密码（明文，由前端加密后传输）、角色选项（学生）。
- **动作**：系统将账号与密码的哈希值和数据库中存储的哈希值比对，同时校验角色是否匹配。
- **输出**：验证成功则跳转至学生首页；验证失败则在原页面显示错误提示"账号或密码错误，请重试"，并清空密码输入框。
- **异常流**：连续输错密码5次，该账号锁定30分钟，期间无法登录，并显示提示信息。

**FR-STU-002：课程查询**
- **描述**：学生可在课程查询功能区按学年、学期浏览当前可选的所有课程信息。
- **前置条件**：学生已成功登录。
- **输入**：查询筛选条件（学年、学期，可为空则返回全部课程）。
- **动作**：系统根据输入条件查询课程数据库，返回匹配的课程列表。
- **输出**：课程信息列表，每条记录包含：课程编号、课程名称、开课教师、课程学时、课程容量、已选人数、开课时间、开课地点。

**FR-STU-003：成绩查询**
- **描述**：学生可在成绩查询子系统中按学年查询个人已修课程的成绩，并支持对查询结果进行排序。
- **前置条件**：学生已成功登录；所查询学年的成绩已由教师录入并由管理员发布。
- **输入**：学年（如：2022-2023），排序方式（升序/降序，默认按课程编号排序）。
- **动作**：系统以学生学号和所选学年为条件，检索成绩表，返回结果后在内存中按指定排序规则排列。
- **输出**：成绩列表，每条记录包含：课程名称、课程性质（必修/选修）、学分、成绩（百分制数值）、绩点；列表底部汇总当前学年总学分、平均绩点。

**FR-STU-004：选课**
- **描述**：在选课子系统中，学生在选课开放时间内选定所需学年学期的课程。
- **前置条件**：学生已成功登录；当前日期在教务处设定的选课开放时间段内；目标课程剩余容量＞0。
- **输入**：目标课程编号（可通过课程查询获得）。
- **动作**：系统检查选课时间有效性→检查课程容量→检查是否重复选课→向选课关系表插入记录→课程已选人数加1。
- **输出**：选课成功：提示"《[课程名称]》选课成功！"；选课失败：根据原因分别提示"课程名额已满"、"已在选课时间外"、"您已选该课程"。

**FR-STU-005：退课**
- **描述**：学生对已选但不再需要的课程发起退订操作。
- **前置条件**：学生已成功登录；当前日期在选课开放时间段内；学生已选该课程。
- **输入**：目标退订课程编号。
- **动作**：系统删除该学生与该课程的选课关系记录，并将该课程的已选人数减1。
- **输出**：退课成功提示"《[课程名称]》退课成功！"；若该课程未被该学生选择则提示"操作无效：您未选择该课程"。

**FR-STU-006：密码修改**
- **描述**：学生可修改个人账户密码。
- **前置条件**：学生已成功登录。
- **输入**：当前密码、新密码、确认新密码（三字段）。
- **动作**：系统验证当前密码正确性→验证新密码与确认密码一致→验证新密码强度（不少于8位，含字母和数字）→更新数据库密码哈希值。
- **输出**：修改成功提示"密码修改成功，请重新登录"，并强制用户退出登录；若验证失败则显示对应错误信息。

#### 3.2.2 教师端功能需求（FR-TEA）

**FR-TEA-001：教师登录**
- **描述**：教师输入账号、密码并选择"教师"角色完成身份验证，进入教师功能主界面。
- **前置条件**、**输入**、**动作**、**输出**及**异常流**：与FR-STU-001类似，仅角色验证为"教师"。

**FR-TEA-002：个人信息查询与修改**
- **描述**：教师可以查询并修改自己的基本档案信息。
- **前置条件**：教师已成功登录。
- **输入（查询）**：无（默认显示本人信息）。
- **输出（查询）**：显示教师档案，包含字段：工号、姓名、性别、出生年月、政治面貌、最高学历、联系电话、联系地址。
- **输入（修改）**：需修改的字段值（姓名、政治面貌、联系电话、联系地址支持修改；工号、性别、出生年月不可修改）。
- **动作**：系统校验修改字段的格式合法性（如电话号码须为11位数字），校验通过后更新数据库。
- **输出（修改）**：提示"信息修改成功"，并刷新显示最新数据。

**FR-TEA-003：学生信息查询**
- **描述**：教师可查询所带班级的相关学生信息。
- **前置条件**：教师已成功登录。
- **输入**：班级名称（支持精确查询）或学生姓名。
- **动作**：系统以教师ID关联其所带班级，在该范围内检索学生信息。
- **输出**：学生信息列表，每条记录包含：学号、姓名、班级名称；可进一步点击查看该学生的历史成绩列表。另显示班级人数汇总。

**FR-TEA-004：成绩录入**
- **描述**：教师为所带班级学生录入指定课程的成绩。
- **前置条件**：教师已成功登录；当前处于成绩录入有效期内；目标学生已选该课程。
- **输入**：学生学号（或从列表中选择）、课程编号、成绩分值。
- **动作**：系统校验分值是否为0至100之间的整数→校验学生是否已选该课程→写入或更新成绩数据库。
- **输出**：提示"《[学生姓名]》[课程名称]成绩录入成功（[分值]分）"；若输入无效，提示具体错误原因。

**FR-TEA-005：信息打印**
- **描述**：教师可将个人信息或所带班级的学生成绩单生成报表并打印。
- **前置条件**：教师已成功登录。
- **输入**：打印内容选择（"个人信息"或"学生成绩单"）、打印参数（如成绩单的班级、学年学期）。
- **动作**：系统生成对应PDF格式文档（适配A4纸排版）。
- **输出**：弹出PDF预览窗口，用户可选择直接打印或另存为文件。

#### 3.2.3 管理员端功能需求（FR-ADM）

**FR-ADM-001：管理员登录**
- **描述**：管理员输入账号、密码并选择"管理员"角色完成身份验证，进入管理员后台。
- **异常流**：同FR-STU-001，连续失败5次锁定账号。

**FR-ADM-002：学生信息管理**
- **描述**：管理员对全校学生的档案进行增删改查操作。
- **前置条件**：管理员已成功登录。
- **输入（新增）**：学生学号、姓名、性别、出生年月、所在班级、初始密码等必填字段。
- **输入（修改）**：学号（定位记录）、待修改字段值。
- **输入（删除）**：学号（定位记录）。
- **动作**：对学生信息表执行相应数据库操作；删除操作需二次确认。
- **输出**：操作成功后刷新展示最新数据列表；若学号重复等违反约束，显示对应错误提示。

**FR-ADM-003：教师信息管理**
- **描述**：管理员对全校教师的档案进行增删改查操作，逻辑同FR-ADM-002，操作对象为教师档案表。

**FR-ADM-004：管理员自身信息维护**
- **描述**：管理员可修改自身的姓名、联系方式等基本信息。
- **前置条件**：管理员已成功登录。
- **输入**：待修改字段（姓名、联系电话）及新值。
- **动作**：校验字段格式后更新管理员档案表。
- **输出**：提示"个人信息修改成功"。

### 3.3 性能需求

| 指标 | 要求 |
|---|---|
| 页面响应时间 | 普通查询类操作（课程查询、成绩查询）的响应时间 ≤ 2秒（在10Mbps网络环境下）|
| 报表生成时间 | PDF格式成绩单或个人档案报表生成时间 ≤ 5秒 |
| 并发支持 | 选课高峰期需支持至少1000名学生同时在线提交选课操作，且数据一致性不受影响 |

### 3.4 软件系统属性

**（1）安全性**
- 采用基于角色的访问控制（RBAC），确保学生账号绝对不能访问成绩录入、学生信息管理等接口，不同角色间接口严格隔离。
- 用户密码在数据库中只保存SHA-256哈希值，不存储明文。
- 所有页面通过HTTPS协议通信，防止数据传输中的中间人攻击。

**（2）可靠性**
- 采用三层B/S分层架构（表现层、业务逻辑层、数据访问层），各层独立部署，降低层间耦合，单层故障不影响其他层的基本运转。

**（3）易用性**
- 学生完成"选课"这一核心操作，从登录成功到选课完成，操作步骤不超过5步。
- 所有表单须提供输入合法性的即时反馈提示（如密码长度不足时，在输入框旁实时显示提示文字）。
